### 1.2 技术架构

- **轻量系统（mini）**：MCU，最小 **128 KiB** 内存；
- **小型系统（small）**：应用处理器，最小 **1 MiB** 内存；
- **标准系统（standard）**：最小 **128 MiB** 内存，支持完整应用框架、ArkUI、分布式能力。

## 2. 与华为 HarmonyOS 的精确关系

### 2.1 一句话区分

**OpenHarmony 是“开源的根/底座”，HarmonyOS 是“华为基于该底座做的闭源商用发行版”。**  
不是“OpenHarmony 是 HarmonyOS 的开源版”这么简单：OpenHarmony 由基金会治理、Apache 2.0、任何厂商都能做发行版；HarmonyOS 由华为控制、闭源、含华为专有服务。

### 2.2 对比表

| 维度 | OpenHarmony | HarmonyOS |
|---|---|---|
| 性质 | 开源项目 / 技术底座 | 华为商用操作系统发行版 |
| 治理 | 开放原子基金会 + 项目群 WC/TSC/PMC/SIG | 华为 |
| 许可证 | Apache 2.0 等 | 闭源、专有 |
| 代码 | 社区主线，公开仓库 | 华为基于 OpenHarmony 叠加专有代码 |
| 品牌 | OpenAtom OpenHarmony | HarmonyOS / 鸿蒙 |
| 应用生态 | OpenHarmony API/SDK，`.hap` | HarmonyOS SDK / AGC，`.app/.hap`；HarmonyOS NEXT 起不含 AOSP |
| 设备 | 开发板、行业终端、第三方 IoT、手机/平板/PC 等 | 华为及合作品牌设备 |
| 认证 | “Powered by OpenHarmony”兼容性测评 | 华为商用发布 |
| 当前版本 | **7.0 Release（2026-08-22，API 26.0.0）** | **HarmonyOS 7（2026-09-06 正式发布，API 26）** |

## 6. 最新版本的核验与不确定性

### 6.1 为什么确定是 7.0 Release（2026-08-22）

| 证据 | 内容 |
|---|---|
| docs release-notes 索引 | **“OpenHarmony v7.0 Release (2026-08-22)”**，位于 7.x 第一项 [索引](https://gitcode.com/openharmony/docs/blob/master/zh-cn/release-notes/Readme.md) |
| 7.0 release note 原文 | 标题 **“OpenHarmony 7.0 Release”**；配套 **“Ohos_sdk_public 26.0.0.38 (API Version 26.0.0 Release)”** [原文](https://gitcode.com/openharmony/docs/blob/master/zh-cn/release-notes/OpenHarmony-v7.0-release.md) |
| GitCode 组织公告 | **“OpenHarmony 7.0 Release 版本发布 8月22日”** [组织页](https://gitcode.com/openharmony) |
| manifest tag | `OpenHarmony-v7.0-Release`，提交时间 **2026-08-22 01:03 +0800** [tags](https://gitcode.com/openharmony/manifest/tags) |
| 华为云镜像 | `7.0-Release/` 目录，`code-v7.0-Release.tar.gz` 等，时间戳 **2026-Aug-21/25** [镜像](https://repo.huaweicloud.com/openharmony/os/7.0-Release/) |
| 媒体 | IT之家 **2026-08-21 20:55** 报道“代码已经上传到 GitCode” [IT之家](https://www.ithome.com/0/992/849.htm) |

**结论：** 官方 release-notes 日期是 **2026-08-22**；代码在 8/21 晚已可获取。若写“8/21 发布”会与官方索引差一天，建议写“**2026-08-22（官方 release-notes 索引；代码 8/21 晚已上传）**”。

### 6.2 6.1.1 LTS 是什么？

- `OpenHarmony-v6.1.1-LTS` 标签在多个仓出现，manifest 提交为 **2026-10-31 14:48 +0800**，提交信息 **“init OpenHarmony-v6.1.1-LTS”**。
- kernel_linux_5.10 的该标签提交信息为 **“merge cve-fix-20261028-OpenHarmony-6.1-LTS into OpenHarmony-6.1-LTS”**，明显是 **2026-10-28 CVE 修复**合入后的维护标签。
- docs 仓 **没有** `OpenHarmony-v6.1.1-LTS.md`，release-notes 索引也未列；GitCode 组织公告只列到 7.0（8/22）、6.1 LTS（7/31）、7.0 Beta1（6/12）、6.1 Release（3/8）。

**判断：6.1.1 LTS 是 6.1 LTS 分支的维护/安全标签，不是新的功能 Release，不应称为“最新版本”。**  
来源：[kernel_linux_5.10 tags](https://gitcode.com/openharmony/kernel_linux_5.10/tags)、[manifest tags](https://gitcode.com/openharmony/manifest/tags)（访问 2026-11-02）

### 6.3 其他需要警惕的二手信息

- 维基百科 OpenHarmony 条目把 6.1 写成 2026-05-24、6.1 LTS 写成 2026-05-28，与官方 3/8、7/31 不符；**不要用**。
- Ohosify 2026-10-01 的文章仍写“截至 2026 年 10 月最新是 6.1（2026-03-09）”，漏掉了 7.0；**不要用**。
- 部分博客把 7.0 的发布日期写成 8/8（这是 RoadMap 计划日期，不是实际日期）。
- 部分文章把 “HarmonyOS 6.1.1 (24)” 与 “OpenHarmony 6.1 (23)” 混为一谈；二者 API 编号不同。

### 6.4 当前维护分支（截至 2026-10 安全公告）

2026-10 安全公告列出的受影响/维护版本：**OpenHarmony-5.1.0-Release、OpenHarmony-6.0-Release、OpenHarmony-6.1-LTS**；并明确 **5.0.3-Release 已停止维护**。  
原话：**“OpenHarmony-5.0.3-Release分支当前已停止维护”**  
来源：[2026 年 10 月安全公告](https://lists.openatom.io/hyperkitty/list/security@openharmony.io/message/SQFOVEUMA3FP26J3G27EKUD2VLDY5YYM/)（访问 2026-11-02）

> 7.0 刚发布（8/22），10 月公告尚未列它；这不代表 7.0 不受维护，而是公告按已发现的 CVE 分支列示。

## EXPAND

- **LEAD: 7.0 的 API diff 与行为变更清单（`zh-cn/release-notes/api-diff/v7.0`、`changelogs`）尚未逐条读** — WHY: 回答“从 6.1 迁移到 7.0 要改什么”必须靠 API diff，而不是版本概述；这也是企业选型的核心 — ANGLE: `git clone --depth 1 -b OpenHarmony-7.0-Release https://gitcode.com/openharmony/docs`，读 `zh-cn/release-notes/api-diff/v7.0` 与 `changelogs`。
