## 2. 官方三条移植指南：路径与步骤骨架

索引页：`docs/zh-cn/device-dev/porting/Readme-CN.md`（[源码](https://gitee.com/openharmony/docs/blob/master/zh-cn/device-dev/porting/Readme-CN.md)）。设备分级原文：

> 「轻量系统类设备 内存>128KB LiteOS-M｜小型系统类设备 内存>1MB、有MMU LiteOS-A、Linux｜标准系统类设备 内存>128MB Linux」

### 2.1 轻量系统（mini / MCU）— `porting-minichip-*.md`

文件族（实测存在）：`porting-minichip-overview / prepare / kernel / subsys-{overview,startup,filesystem,security,communication,driver,others} / verification / porting-chip-faqs`。

步骤骨架：
1. **移植准备**：下载代码、搭编译环境、熟悉 gn/ninja 构建框架。
2. **移植内核**（`porting-minichip-kernel.md`）：
   - 芯片架构：`kernel/liteos_m/arch` 已支持 arm9/cortex-m3/m4/m7/m33、csky v2、risc-v(nuclei/riscv32)、xtensa lx6；**不在表内才需自己做 arch**。
   - 接入厂商 SDK：SDK 放 `device/`，编译/打包脚本并入框架；
   - 自定义 `target_config.h`，官方参考路径就是海思：
     「`device/hisilicon/hispark_pegasus/sdk_liteos/platform/os/Huawei_LiteOS/targets/hi3861v100/include/target_config.h`」；
   - 中断接管：`LOSCFG_USE_SYSTEM_DEFINED_INTERRUPT=NO` 时把 `PendSV_Handler→HalPendSV`、`SysTick_Handler→OsTickHandler`。
   - 内核子系统：`vendor/.../config.json` 加 `kernel/liteos_m`，在 `kernel/liteos_m/BUILD.gn` 开关 cpp/cpup/exchook/kal/fs/backtrace。
3. **移植子系统**：startup、文件、安全、通信（Wi-Fi/BT）、外设驱动（GPIO/I2C/SPI）、其他。
4. **移植验证**（`porting-minichip-verification.md`）：加 `test` 子系统 + `xts_acts/xts_tools`，链接 `libmodule_ActsXxxTest.a`（必须 `-lhctest -lbootstrap -lbroadcast`，且夹在 `--whole-archive` 之间），串口看报告，失败项整改。

> ⚠️ **该族文档自带时效警告**（很关键）：
> 「本文档适用于OpenHarmony **LTS 3.0.1及之前版本**的轻量系统的适配。」（`porting-minichip-overview.md`）
> 也就是说：**照着 3.0.1 的 mini 指南移植 6.x/7.0 会踩构建体系差异**，需以 `kernel_liteos_m` README 与 6.x 实际 `config.gni` 为准。

### 2.2 小型系统（small / MMU）— `porting-smallchip-*.md`

骨架：
1. **移植须知**（`prepare-needs`）：现成参考板 = `hispark_taurus`（LiteOS-A + linux-4.19，ARM Cortex-A7，8G ROM/1GB RAM，VFAT+EXT4，eMMC4.5）、`hispark_aries`（LiteOS-A，16M/512M，JFFS2，SPI NOR）。
2. **编译构建**（`prepare-building`）：建 `device/{厂商}/{板}`，写 `config.gni`（kernel_type/board_cpu/board_toolchain…）、`BUILD.gn`；`hb set` + `hb build`。
3. **内核移植**二选一：
   - **LiteOS-A**（`kernel-a`）：仅 ARMv7-A；七步初始化——`target_config.h` 的 `DDR_MEM_ADDR/DDR_MEM_SIZE` → `board.ld` 链接脚本；`g_archMmuInitMapping` MMU 映射；多核 `SmpOps/SmpCpuOn`；`reset_vector_{up,mp}.S`；C `main` 建 `SystemInit` 任务；`SystemInit` 内 `DeviceManagerStart()` 加载 `hdf.hcs` 与驱动。
   - **Linux**（`kernel-linux`）：基线 **Linux 5.10 LTS**（`kernel/linux-5.10`）；以 hi3516dv300 为范例新建 `hi3516dv300_small_defconfig` 与 `hi3516dv300_small_patch`（含 `hdf.patch`）；改 `kernel_module_build.sh`/`kernel.mk`；给出 hi3516dv300 的 uboot `bootargs`（`mem=128M … blkdevparts=mmcblk0:1M(boot),9M(kernel),50M(rootfs),50M(userfs)`）。
4. **驱动移植**：`driver-overview` 分平台驱动（SoC 内 GPIO/I2C/SPI）与器件驱动（LCD/TP/WLAN）；`driver-plat` 在 `device/{vendor}/{soc}/drivers` 下按 HDF 模型“注入实例”（以 GPIO 为例）；`driver-oom`（器件）。
5. 验证：init → shell → NFS 挂载调测。

### 2.3 标准系统（standard）— `standard-system-porting-guide.md`

骨架（1.6 万字节，四章）：
1. **定义开发板/产品**：`//vendor/{Vendor}/{Product}/config.json`（`type=standard`、`target_cpu`、`device_company`、`board`、`enable_ramdisk`、`subsystems`）。原文给的最省事路径：
   > 「建议先拷贝 **Hi3516DV300** 开发板的配置文件，删除掉 `hisilicon_products` 这个子系统。」
2. **内核移植**：在 `build/subsystem_config.json` 注册 `{SOC}Vendor_products`（path 指向 `device/{Vendor}/{SOC}/build`），在 `device/.../build` 写 `BUILD.gn` + `ohos.build` + `kernel/linux/standard_patch_for_4_19.patch`；产物 = `packages/phone/images/uImage` 与 `uboot`。
3. **用户态启动引导**：init 通过 cmdline `init=/init` 启动 → tmpfs/procfs/dev → ueventd → 挂 system/vendor → samgr → foundation → appspawn；新平台必须补 `/vendor/etc/init/init.{hardware}.cfg`（装 ko、设 `/proc` 节点）。
4. **HDF 驱动移植**：LCD（`drivers/hdf_core/framework/model/display/driver/panel` 里 `RegisterPanel`）、触摸屏、WLAN（实现 `HdfChipDriverFactory` / `HdfChipDriver` / `NetDeviceInterFace`，代码放 `//device/{SoC厂商}/peripheral/wifi/{chip}/`）。
5. 移植示例指向 DAYU200（RK3568）。

配套还有 `porting-linux-kernel.md`：**“不改内核源码、以补丁方式把 OpenHarmony 内核态特性叠到已有厂商 Linux 内核”** 的快速路线（准备构建环境 → 移植内核态基础代码 → 移植必选特性 HDF → 编 Image → 可选跑 HDF 测试用例），这是给“新 SoC + 厂商 BSP”最实用的一篇。

## 5. 把 OpenHarmony 移植到“一颗新海思 SoC”到底要做什么

按指南原文可拆成 6 层（以 Hi3403 的真实案例校准）：

1. **Bootloader**：可用厂商 uboot 或开源 uboot。
   > 「可以使用芯片厂商自带的 Bootloader，或者是开源 Uboot 等加载内核镜像。比如为支持 Hi3516DV300 开发板，OpenHarmony 引入的开源 Uboot。」（`porting-smallchip-kernel-linux.md`）
   Hi3403 更省事：「鸿蒙版本的 uboot 是直接使用各芯片 SDK 版本的 uboot」；但要改 **ATF BL33 指向 OpenHarmony uImage**。
2. **内核**：选与社区基线同版或邻近的 LTS（新 SoC 走 **Linux 6.6.y**；老平台 5.10；MCU 走 LiteOS-M）。工作 = 厂商 SDK kernel patch 与 OpenHarmony 特性 patch 合流，解决冲突；产出 `uImage`（standard 还要 `uboot`）。
3. **HDF 平台驱动**：GPIO/I2C/SPI/UART/PWM/MMC 等，每个都是“向 HDF 模型注入实例”（`porting-smallchip-driver-plat.md` 的 GPIO 模板）。
4. **器件/HDI 层**：显示（FB/DRM + TDE）、媒体（VI/VPSS/VENC/VDEC/AIO 封装 MPP）、音频、Camera、HUKS（OTP/密码引擎）。Hi3403 案例里 HAL 是**最大工作量**：`hal_display`（display_layer/gfx/gralloc）、`hal_media`、`hal_huks` 三套 HDI + 中间件。
5. **产品与构建配置**：`vendor/{厂商}/{产品}/config.json` 选子系统；`device/board/{厂商}/{板}/{linux,liteos_a}` 的 `config.gni` + `BUILD.gn`；`build/subsystem_config.json` 注册内核子系统；`init.{hardware}.cfg`、`fs.yml`、`hdf.hcs`。
6. **验证**：XTS（`xts_acts`/`xts_tools`，必须链 `-lhctest -lbootstrap -lbroadcast`）+ 厂商 SDK 功能测试（Wi-Fi/BT/OTA）。

**现实工作量判断**（有依据的推断，非官方口径）：
- 小型系统（Linux）新 SoC：**3–6 人月**起步；其中 60% 在 HAL/HDI 与内核 patch 融合，20% 构建/产品配置，20% XTS 调优。依据：Hi3403 从首版文档（2025-09-15）到可用（2026-03-05，含编译/启动/HUKS/third_party 补齐）约 **6 个月**，且是**芯片原厂 + 润开鸿**联合投入。
- 标准系统新 SoC：**不建议**。显示/GPU/合成、128MB+ 内存、完整 HDF + ArkUI 才是门槛；且官方自 3.2 起连 Hi3516 都不再验证，**没有可抄的“海思标准系统模板”**（`hispark_taurus_standard` 最后实质提交 2025-03-14）。
- 轻量系统（LiteOS-M）：**1–2 人月**，前提是 arch 已在支持表内（cortex-m/rl78 之外的 riscv32 也有）；难点是厂商 SDK 以**闭源库**形式给出（Hi3861 的 `liblitekernel_flash.a`），只能通过 `target_config.h` + 中断重定向 + 链接脚本适配。

## 6. LiteOS 与海思的关系（不是“历史”，是“现在进行时”）

- **命名即证据**：Hi3861 的 SDK 根目录就叫 `device/hisilicon/hispark_pegasus/sdk_liteos`，内核以库形式提供：
  > 「因为海思的 SDK 是以**库文件**的形式提供的，所以不同的 Hi3861 芯片开发板启动流程是一样的。」（[电子工程专辑分析](https://www.eet-china.com/kj/1660278189.html)，2022-08-12）
  启动链：RomBoot → FlashBoot(A/B) → LoaderBoot → CommonBoot → `main`（`liblitekernel_flash.a`）→ `LOS_KernelInit` → `AppInit`（`libwifiiot_app.a`）→ `OHOS_Main/OHOS_SystemInit` → `LOS_Start`。
- **OpenHarmony 侧血缘**：`kernel_liteos_a` README 首句「OpenHarmony LiteOS-A 内核是基于 **Huawei LiteOS** 内核演进发展的新一代内核」；`kernel_liteos_m` 同源。小型系统 hi3516/3518 走 LiteOS-A，hi3861/ws63 走 LiteOS-M。
- **许可分层**：Hi3861 SDK 的 `build/libs`、`build/basebin` 属 **EULA**（不可开源修改），自研代码 Apache-2.0，`third_party/mbedtls` GPL-2.0——**移植时可以改 adapter，不能改内核库**，这是 Hi3861 生态“能做应用、难做内核创新”的根本原因。
- **厂商 SDK 获取**：Hi3861/WS63 走 `gitee.com/HiSpark`（`ohos_ws63`、`fbb_ws63`）；Hi3403/3519 走 `git clone https://gitee.com/HiSpark/pegasus.git` + `git submodule update platform/ss928v100_clang`；Hi3516DV300 的 MPP 库在 `device_soc_hisilicon/hi3516dv300/sdk_linux`（含 EULA LICENSE 文件）。
