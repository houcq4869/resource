## 1. 解读对象盘点：这份源码是什么

| 事实 | 证据 |
|---|---|
| **版本 = OpenHarmony 6.1 LTS**（标准系统） | `build/version.gni`：`sdk_version = "6.1.0.43"`、`api_version = "23"`；`.repo/manifests/default.xml`：`<default revision="OpenHarmony-6.1-LTS">` |
| repo 多仓组织，**非单体仓库** | `.repo/` 目录 + manifest 分层：`ohos/ohos.xml`（**494 个平台仓**）+ `chipsets/*.xml`（芯片组仓：dayu200(RK3568)、hispark、bq3588、phytium、qemu、p7885 等） |
| 托管远端 = **GitCode**（Gitee 已停滞） | manifest 双 remote 定义，default remote 指向 `gitcode.com/openharmony` |
| 总体积 ≈ **226 GB**（含 `out/` 构建产物与 `prebuilts/` 工具链） | `du -sh` 实测 |
| 本地树额外含**展锐 P7885 芯片仓** | 顶层 `kernel_unisoc_p7885/`（对应 7.0 起新增的 P7885 参考板） |

## 2. 顶层目录地图（本仓库实测）

```
oh_lts/
├── kernel/               内核：linux-5.10 / linux-6.6（板级补丁在 kernel/linux/patches）、liteos_a / liteos_m / uniproton
├── kernel_unisoc_p7885/  展锐 P7885 内核仓（芯片厂商定制，独立于通用 kernel/linux）
├── drivers/              HDF 驱动框架（drivers_hdf_core 等）+ 外设/平台驱动
├── device/               板级配置三级结构之一：board（开发板）/ soc（芯片）/ qemu
├── vendor/               板级配置三级结构之二：厂商产品配置（hisilicon、hihope、ohemu/QEMU、default…）
├── productdefine/        板级配置三级结构之三：产品定义（common_modules 等），决定拼装哪些子系统/部件
├── base/                 「基础」子系统集：account、global(i18n)、hiviewdfx(DFX)、notification、powermgr、
│                         security、sensors、startup(init)、telephony、usb、useriam、web(ArkWeb)、tee…
├── foundation/           「foundation」子系统集（核心运行时）：ability(AbilityRuntime)、arkui(ArkUI)、
│                         graphic(图形栈)、communication(IPC/软总线)、bundlemanager(包管理)、window(窗口)、
│                         resourceschedule(资源调度)、distributeddatamgr/distributedhardware(分布式)、
│                         multimedia、filemanagement、systemabilitymgr(SA机制)、multimodalinput…
├── domains/              「领域」子系统集：advertising、game
├── arkcompiler/          方舟编译器：ets_runtime(ArkTS运行时)、runtime_core(字节码)、toolchain 等
├── commonlibrary/        公共库：ets_utils 等
├── interface/            SDK 接口层：sdk_c、sdk-js、各 Kit 的 API 定义（应用 → 系统的边界）
├── applications/         系统应用（settings、camera、photos、sample…）
├── build/ + build.py/sh   构建系统：GN/Ninja + hb 命令行；subsystem_config.json（子系统注册表）、version.gni（版本号）
├── developtools/         开发者工具：hdc(≈adb)、hiperf/smartperf(性能)、hapsigner(签名)、packing_tool、
│                         profiler、sdk_*（SDK 打包）、ace_*2bundle(前端编译)
├── third_party/          三方组件（musl、openssl、icu、chromium/webengine…）
├── prebuilts/            预编译工具链（clang、nodejs、python…）
├── docs/                 官方文档仓（中/英）：release-notes(1.0→6.1 全时间线)、application-dev、device-dev、design
├── docs_cangjie/         仓颉语言文档
├── ide/                  IDE 相关（DevEco Studio 侧内容）
├── test/ + testfwk/xts/  测试体系：XTS 兼容性测试等
├── qemu-run/             QEMU 运行脚本（无板也能跑标准系统）
└── out/                  构建产物
```

**注意**：`base/ foundation/ domains/` 是三类「子系统集」目录名的字面体现，但**目录 ≠ 子系统**——子系统是逻辑注册在 `build/subsystem_config.json` 的 59 个条目，部件（bundle.json）才是构建单元，仓是 git 单元。三层映射：**子系统 → 部件 → 仓**（详见调研报告 04 详档）。

## 3. 子系统体系（`build/subsystem_config.json` 实测：59 个）

ability, accesscontrol, account, advertising, ai, appexecfwk, applications, arkcompiler, arkui, barrierfree, bundlemanager, castplus, commonlibrary, communication, customization, developtools, deviceprofile, distributeddatamgr, distributedhardware, filemanagement, game, global, graphic, hdf, hiviewdfx, ide, inputmethod, iothardware, kernel, llvmproject, location, msdp, multimedia, multimodalinput, notification, ostest, powermgr, print, request, resourceschedule, sdk, security, sensors, soc_p7885, startup, systemabilitymgr, tee, telephony, testfwk, theme, thirdparty, time, updater, usb, useriam, utils, web, window, xts

> 其中 `soc_p7885` 是芯片专属子系统的例子（P7885 板的私有部件挂载点）——印证「产品拼装」机制：产品在 `productdefine` 里选子系统清单，芯片/板/厂商各自贡献部件。
