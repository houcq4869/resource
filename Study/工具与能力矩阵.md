# RTOS 工具与能力矩阵（含开发工具 / IDE 专项）

> **文档定位**：面向「芯片 / 开发板 Bring-up 与适配」场景，按 E2E 各阶段给出**工具与能力矩阵**，并新增**开发工具 / IDE 专项**维度。正文只放**矩阵与对比（简洁直观）**，逐工具细节下沉到附录。
>
> **与《调研汇总》的关系**：本文是 `[[调研汇总]]` 的**补充篇**——《调研汇总》回答"每个 RTOS 各阶段有哪些工具、能力是什么"，本文补上**开发工具/IDE 维度、各阶段工具的优劣对比与量化统计、跨 RTOS 通用工具标注**三块，并以矩阵形式重组呈现。
>
> **来源**：各项目/厂商官方文档与仓库、官方 Marketplace 页面，2026-09 联网调研（一手来源优先）。凡未从一手来源确认者标注 `待核实`。详见附录 D，以及 `Study/调研素材/` 下的 5 份逐 RTOS 调研稿。

## 一、口径与图例

### 1.1 E2E 阶段口径（本文含新增 ⓪）

| 代号 | 阶段 | 一句话本质 |
|---|---|---|
| **⓪** | **开发环境 / IDE**（新增） | 开发者**第一次接触**工具链的入口层，横跨 ②③④⑤——决定"上手门槛" |
| ① | 选型评估 | 检索支持矩阵与上游证据，评估"复用 vs 自研" |
| ② | 工程配置与代码生成 | 把硬件约束转成机器可编译的声明 |
| ③ | 编译构建 | 在 host 上交叉编译出 target 镜像，并保证可复现 |
| ④ | 烧录下载 | 把镜像写入持久存储并让启动链找到它 |
| ⑤ | 在线调试 | 在 target 上制造受控的暂停与观察 |
| ⑥ | 跟踪与性能调优 | 低侵入记录"时间轴上发生了什么" |
| ⑦ | 测试验证 | 把"能跑"变成"可证明正确且可回归" |
| ⑧ | 自动化 CI | 把适配过程变成"每次提交都重新验证"的流水线 |
| ⑨ | 维护与 OTA | 让已出货设备可远程原子更新并回滚 |

> ⓪ 与 ②③④⑤ 有交集的说明：IDE/开发工具**不是一个新的时间节点**，而是**贯穿配置→构建→烧录→调试的入口层**。本表把它单列，是为了让"上手门槛"这一竞争维度可见（这正是 `参考信息.md`、`LiteOS 方案` 反复强调的客户痛点）。

| 符号 | 含义 | 判定 |

**三处最值得注意的差异**
1. **VS Code 官方扩展**：只有 **RT-Thread（官方 2~3 个）** 与 **OpenVela（官方 2 个）** 有官方发布者扩展；**FreeRTOS / Zephyr / ThreadX 均无官方扩展**（Zephyr 的两个扩展是第三方、被官方文档收录）。
2. **IAR 是覆盖面最广的商业 IDE**：是 **Zephyr 官方一等工具链**、**ThreadX 有官方 C-SPY 插件**、**FreeRTOS 插件内置**、**RT-Thread/NuttX 可经导出器接入**。
3. **Keil 绑定 Arm 生态**：在 FreeRTOS（CMSIS-Pack）与 RT-Thread（scons 导出 + 官方 pack）可用，但**无 Zephyr 官方支持**；ThreadX 侧只有原厂 pack。

#### ① 选型评估

| RTOS | 代表工具 | 优势 | 局限 | 适用场景 |
|---|---|---|---|---|
| FreeRTOS | Supported Devices + LTS | 40+ 架构 port 一目了然；LTS 长期维护 | 仅"内核 port"，不含中间件可得性 | MCU 通用选型 |
| RT-Thread | BSP 列表 + 软件包平台 | 362 个 BSP / 875 个包，生态最丰富 | 官方 README 口径滞后、自相矛盾 | 国内产品快速选型 |

### A.1 VS Code 生态（跨 RTOS 主战场）

- **介绍**：VS Code 本体是**编辑器而非 IDE**（不含编译器与调试器），能力由"通用扩展 + 原厂扩展 + 通用调试扩展"三层拼装。
- **分层**：① 语言层 `clangd`（依赖 `compile_commands.json`）或微软 C/C++ 扩展；② 调试层 `Cortex-Debug`（J-Link / OpenOCD / ST-LINK GDB server / pyOCD / Black Magic，含 SWO/RTT 解码与 RTOS 线程视图）；③ 原厂层（ST/NXP/Nordic/Espressif/Arm/Infineon/Silabs/IAR 均有官方扩展）。
- **覆盖环节**：②③④⑤⑥（因扩展而异）。
- **宿主 / 许可**：Win/Linux/mac；本体免费，扩展多专有。
- **优势**：同一编辑器 + 同一套源码体验横跨几乎所有 RTOS 与芯片；原厂正**把 VS Code 当主力方向**（ST 明确资源转向 VS Code 版；Silicon Labs SS6 以 VS Code 为主 IDE）。
- **局限**：**RTOS 线程感知取决于后端 GDB server**（不如商业 IDE 统一）；无原生深度指令 trace/ETM；工具链需自行拼装。
- **关键扩展对照**：

| Cortex-Debug + mcu-debug RTOS Views | 通用（Arm Cortex-M） | FreeRTOS（多 RTOS，取决于 GDB server） | 开源 MIT |
| STM32CubeIDE for VS Code | STM32 | FreeRTOS / ThreadX | 免费专有 |
| MCUXpresso for VS Code | NXP | FreeRTOS / Zephyr | 免费专有 |
| nRF Connect for VS Code | nRF Connect SDK（Zephyr） | 自带 RTOS 感知调试器 + Thread Viewer | 免费专有 |

| RT-Thread 官方扩展（`rt-thread-smart` / `rt-thread-studio`） | RT-Thread | J-Link/ST-Link 调试 | GPLv2 / 专有 |

### A.2 Keil MDK / Keil Studio / CMSIS-Toolbox

- **介绍**：Arm 官方 IDE 与工具链。µVision 为传统 Windows IDE；**Keil Studio Pack 是 MDK v6 的 VS Code 扩展形态**（含 Arm CMSIS Solution + CMSIS Debugger，调试经 pyOCD 或 J-Link GDB Server）；CMSIS-Toolbox `cbuild` 为命令行构建入口。

### A.9 开源公共地基（GDB / OpenOCD / pyOCD / J-Link GDB Server / CMake / Ninja / ccache）

- **局限**：只是零件，需自行组装（工具链路径、GDB server、`compile_commands.json`、`launch.json`）；RTOS 感知与 trace 深度有限。

### D.1 待核实项（跨 5 类 RTOS + 通用工具）

1. **Keil µVision 对 FreeRTOS / ThreadX 的原生内核视图**：Arm 官方 RTOS 感知文档面向 RTX5；FreeRTOS 经 CMSIS-RTOS2/Event Recorder，ThreadX 仅有原厂 pack——是否存在原生视图无一手明文。
2. **IAR 宿主 OS 完整矩阵**：新版产品页称 Linux + Windows，旧版安装文档仅 Windows；Linux 起始版本未确认。
3. **NXP ThreadX 口径差异**：官方页称"SDK 2.15 之后停供"，但 keil.arm.com 存在基于 SDK 2.16.0 的 `NXP::AZURE_RTOS@2.0.0`。
4. **NuttX Windows 原生构建现状**：官方文档有 `CONFIG_WINDOWS_NATIVE=y` 描述但标注 "work in progress"，当前是否积极维护未确认；openvela 明确仅支持 Ubuntu、不支持 WSL/Docker。
5. **RT-Thread 待核实**：Studio 是否"仅 Windows"（仅安装包佐证）；`--target=eclipse` 与官方 FAQ 冲突；`zig` 目标未见生成分支；Percepio Tracealyzer 是否有官方 RT-Thread 支持；CLion 官方支持仅为推论。
6. **Zephyr 待核实**：`IDE for Zephyr`（mylonics）与 `Workbench for Zephyr`（Ac6）为**第三方**扩展（被官方文档收录≠官方背书）；Zephyr Eclipse 插件已停滞；SEGGER Ozone 的 Zephyr 感知仅保证 Nordic 分支。
7. **通用工具待核实**：Arm Development Studio 宿主 OS；e² studio / Simplicity Studio 6 / RT-Thread Studio 许可条款；Cortex-Debug 的 RTOS 明细清单；部分开源工具的精确 SPDX。
8. **数量与版本类数据**为 **2026-09 快照**，随时间变化；正式采用前请核对官方最新文档与 EULA。
