### 2.3 一句话结论

- **"无自研 IDE、走通用工具"是主流**：FreeRTOS（CMSIS-Pack 分发）、Zephyr（VS Code 生态最厚）、ThreadX（原厂 SDK 承载）均不自研 IDE；唯一例外是 RT-Thread Studio（Eclipse 定制）。
- **VS Code 支持梯度**：Zephyr（官方扩展双雄）＞ FreeRTOS/OpenVela（通用可行/仅 sim 文档）＞ RT-Thread（配置生成 + 垂直扩展）＞ ThreadX（无官方路径）。
- **RTOS 感知的分水岭在工具链而非 IDE**：cortex-debug/Ozone/J-Link/OpenOCD 都做"感知"，但感知清单各不相同——RT-Thread 是唯一在 OpenOCD/J-Link/SystemView/Tracealyzer 四家官方清单上**全部缺席**的主流 RTOS（详见第三章矩阵）。

### E.1 VS Code 生态（跨 RTOS 主战场）

- **介绍**：VS Code 本体是**编辑器而非 IDE**（不含编译器与调试器），能力由"通用扩展 + 原厂扩展 + 通用调试扩展"三层拼装。
- **分层**：① 语言层 `clangd`（依赖 `compile_commands.json`）或微软 C/C++ 扩展；② 调试层 `Cortex-Debug`（J-Link / OpenOCD / ST-LINK GDB server / pyOCD / Black Magic，含 SWO/RTT 解码与 RTOS 线程视图）；③ 原厂层（ST/NXP/Nordic/Espressif/Arm/Infineon/Silabs/IAR 均有官方扩展）。
- **覆盖环节**：②③④⑤⑥（因扩展而异）。**宿主 / 许可**：Win/Linux/mac；本体免费，扩展多专有。
- **优势**：同一编辑器 + 同一套源码体验横跨几乎所有 RTOS 与芯片；原厂正**把 VS Code 当主力方向**（ST 明确资源转向 VS Code 版；Silicon Labs SS6 以 VS Code 为主 IDE）。
- **局限**：**RTOS 线程感知取决于后端 GDB server**（不如商业 IDE 统一）；无原生深度指令 trace/ETM；工具链需自行拼装。
- **适用**：跨平台 / 开源工具链团队、需要统一编辑器体验的多芯片项目。

### E.2 Keil MDK / Keil Studio / CMSIS-Toolbox

- **介绍**：Arm 官方 IDE 与工具链。µVision 为传统 Windows IDE；**Keil Studio Pack 是 MDK v6 的 VS Code 扩展形态**（含 Arm CMSIS Solution + CMSIS Debugger，调试经 pyOCD 或 J-Link GDB Server）；CMSIS-Toolbox `cbuild` 为命令行构建入口。
- **覆盖环节**：②③④⑤⑥。**宿主**：µVision 仅 Windows；Keil Studio 随 VS Code 跨平台。**许可**：商业；MDK-Community 非商用免费。

### E.3 IAR Embedded Workbench / C-SPY / C-STAT / C-RUN

- **介绍**：IAR 的商业编译器 + IDE + C-SPY 调试器；另有 C-STAT 静态分析与 C-RUN 运行时检查（限 Arm/RX）。

- **局限**：商业授权；部分旧架构按需提供。
- **适用**：对代码质量/安全合规（IAR 有功能安全版）和成熟调试有要求的商业项目。

### E.4 Eclipse 系
