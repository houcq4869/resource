
### 研讨主题：
嵌入式工具链&编译环境：业界主流在Windows上开发（IDE和构建系统），OH开发需搭建Linux环境和复杂构建环境，上手难


### 现状分析
#### 看伙伴：
	ARM架构有配套的Keil(MDK),RISC-V厂商多基于Eclipse开发针对自家芯片的IDR或通用VSCode

| 厂商     | 芯片架构       | 开发环境    | IDE               |
| ------ | ---------- | ------- | ----------------- |
| 芯海、复旦微 | ARM        | Windows | Keil(MDK)         |
| 沁恒     | RISC-V     | Windows | MounRiver Studio  |
| 泰凌微    | RISC-V     | Windows | Telink IOT Studio |
| 博通集成   | RISC-V、ARM | linux   | VSCode            |
| 瑞晟     | RISC-V、ARM | linux   | VSCode            |


#### 看竞品
	成熟商用RTOS以通用工具兼容为主，保障Windows编译，自研工具增效为辅

| RTOS      | IDE开发环境支持                                                                                            |
| --------- | ---------------------------------------------------------------------------------------------------- |
| FreeRTOS  | 无绑定专属IDE、无强制编译环境依赖，支持Keil、VS Code等通用工具，支持Windows环境开发                                                 |
| Zephyr    | 官方不做封闭自研IDE，基于VS Code + Zephyr SDK + CMake/Ninja构建通用工具链，主力依赖Linux编译环境，Windows仅通过WSL适配，无原生Windows编译链路 |
| RT-Thread | 提供自研IDE（RT-Thread Studio）同时兼容VSCode、Keil等通用工具，原生完整支持Windows编译调试                                      |


#### 看自己
	编译依赖强，生态兼容不足，工具链臃肿，开发者迁移成本高，新手落地难度远高于FreeRTOS、RT-Thread

| 厂家建议                                       | 厂家    |
| ------------------------------------------ | ----- |
| 开发环境复杂，没有可视化的工程模板配置，能不能支持keil、IAR这些IDE编译环境 | 芯海科技  |
| 不想在ubuntu环境下开发，希望能直接在windows环境开发           | 沁恒    |
| 配置项过多，链接参数复杂，可以考虑IDE或者IDE集成                | 泰凌微   |
| 组件依赖性比较强，过于依赖三方库，不方便裁剪                     | 瑞昱半导体 |
| 希望能够支持windows环境下keil开发，降低上手难度              | 三表厂商  |


### 研讨建议

1、无需自研专用IDE，兼容keil、IAR以及VS Code等主流IDE即可
2、支持Windows系统，降低shen
