### 一、FreeRTOS

FreeRTOS介绍：MIT 许可的轻量级实时内核（现由 AWS 维护），提供任务/队列/信号量/软定时器，官方 port 覆盖 40+ 架构，是 MCU 领域最通用、成本敏感场景的首选 RTOS。

1、选型评估工具
- FreeRTOS Supported Devices（官方内核 port 列表，覆盖 40+ 架构）
	- 作用：判断目标 MCU 是否已有内核 port，确定移植起点
- FreeRTOS LTS（长期支持版本）
	- 作用：确认长期维护版本，评估维护成本
- EEMBC CoreMark / ULPMark 标准基准
	- 作用：量化吞吐/能效，支撑横向选型对比

2、工程配置与代码生成工具
- 工具1：`FreeRTOSConfig.h`（唯一集中配置头文件）
	- 作用：以编译期宏裁剪内核行为（调度算法、tick 频率、堆方案 heap_1~5、任务/队列上限、调试宏）
- 工具2：原厂图形配置器（STM32CubeMX / MCUXpresso Config Tools / TI SysConfig / Renesas FSP）
	- 作用：图形配置引脚/时钟/外设，并"捎带"生成含 FreeRTOS 的工程骨架（无官方图形配置器时的事实标准）
- 工具3：CMSIS-Pack（`.pdsc` 软件包分发）
	- 作用：开发者可在 IDE 内包管理器中直接管理 FreeRTOS 依赖，免手工集成

3、编译构建工具
- 工具1：Arm GNU Toolchain（`arm-none-eabi-gcc`）
	- 作用：默认交叉编译器，编译内核与应用，产出单一固件镜像
- 工具2：原厂 IDE（STM32CubeIDE / MCUXpresso IDE / CCStudio+TI Arm Clang / e² studio）
	- 作用：一体化 IDE 构建
- 工具3：Keil MDK（armclang）/ IAR Embedded Workbench
	- 作用：商业优化编译器，跨原厂
- 工具4：CMake / CMSIS-Toolbox `cbuild`
	- 作用：无头构建（YAML 工程描述），便于 CI

4、烧录下载工具
- 工具1：调试探针（J-Link/J-Flash / OpenOCD / pyOCD）
	- 作用：FreeRTOS 无专属烧录工具，借探针经 SWD/JTAG 直接编程 Flash
- 工具2：原厂烧录器（STM32CubeProgrammer / UniFlash(TI) / RFP(Renesas) / Simplicity Commander(Silabs)）
	- 作用：多接口（ST-LINK/UART/DFU/CAN/I2C）烧录与校验

5、在线调试工具
- 工具1：GDB + OpenOCD / pyOCD / J-Link GDB Server
	- 作用：源码级断点/寄存器/内存调试（单地址空间可直看全局符号）
- 工具2：内核感知调试插件（Eclipse / IAR / Keil / Ozone / GHS 内置）
	- 作用：查看任务列表、状态、栈、队列等 RTOS 对象
- 工具3：SEGGER Ozone（图形调试器）
	- 作用：图形化源码级调试 + RTOS 感知视图
- 工具4：IAR C-SPY
	- 作用：trace/覆盖率/剖析 + RTOS 感知

6、跟踪与性能调优工具
- 工具1：`vTaskGetRunTimeStats` / `uxTaskGetStackHighWaterMark`（内核自带）
	- 作用：统计各任务 CPU 占用与栈高水位（历史最小剩余）
- 工具2：Percepio Tracealyzer（含 FreeRTOS 免费版）
	- 作用：任务/中断事件时间线、CPU 负载、堆栈可视化
- 工具3：SEGGER SystemView（基于 RTT）
	- 作用：实时记录任务切换/中断/API 事件并可视化，开销极小
- 工具4：CMSIS Event Recorder + Component Viewer
	- 作用：记录 RTOS/中间件事件，在调试器内按 SCVD 展示内核对象

7、测试验证工具
- 工具1：FreeRTOS-Kernel 官方回归测试
	- 作用：验证内核与各 port 正确性
- 工具2：Unity + CMock + Ceedling（MIT）
	- 作用：嵌入式 C 单元测试 + mock 生成 + 构建/测试编排
- 工具3：CBMC（有界模型检查器）
	- 作用：内核级形式化验证
- 工具4：gcov/lcov、clang-tidy/cppcheck
	- 作用：覆盖率统计与静态检查

8、自动化 CI 工具
- 工具1：GitHub Actions（官方仓库）
	- 作用：内核/port 组合的构建与回归流水线
- 工具2：CBMC / Coverity in CI
	- 作用：形式化/静态验证纳入流水线

9、维护与 OTA 工具
- 工具1：AWS IoT OTA（`ota-for-aws-iot-embedded-sdk`，MIT）
	- 作用：与 AWS IoT Core 集成的作业式云下发固件升级
- 工具2：AWS IoT Device Defender
	- 作用：设备安全态势监控、异常行为检测
- 工具3：MCUboot（可选）
	- 作用：通用安全 bootloader（镜像签名、A/B 升级、回滚）
- 工具4：原厂 bootloader / 安全启动组件
	- 作用：设备侧引导与升级

### 二、RT-Thread

RT-Thread介绍：Apache-2.0 国产开源 RTOS，可裁剪内核 + FinSH/MSH 命令行 shell + 设备框架；近 200 个 BSP、370+ 软件包，国内生态最丰富，主打快速选型与低上手门槛。

1、选型评估工具
- 工具1：BSP 列表（近 200 个板级支持包）
	- 作用：评估目标板可复用的板级支持程度
- 工具2：软件包平台（packages.rt-thread.org，370+ 包）
	- 作用：评估中间件/驱动/组件的可复用选型面

2、工程配置与代码生成工具
- 工具1：Env 工具集（menuconfig + pkgs 包管理）
	- 作用：Kconfig 图形化裁剪、软件包下载管理；Windows 免装 Python/SCons、自带 ARM GCC（低门槛关键）
- 工具2：RT-Thread Studio（基于 Eclipse 的一体化 IDE，免费，宿主 Windows）
	- 作用：图形化工程创建/配置/编译/下载/调试一站式

3、编译构建工具
- 工具1：SCons（Python 构建系统，MIT）
	- 作用：脚本化构建；`scons --target=mdk5/iar/vs2012` 一键导出主流 IDE 原生工程（把门槛打下来的关键能力）
- 工具2：RT-Thread Studio 内置构建
	- 作用：IDE 内一站式编译

4、烧录下载工具
- 工具1：RT-Thread Studio 下载功能
	- 作用：IDE 内直接烧录
- 工具2：原厂工具 / 通用探针（ST-LINK / J-Link）
	- 作用：无专属烧录器时借通用通道烧录

5、在线调试工具
- 工具1：RT-Thread Studio 集成 GDB + ST-LINK/J-Link
	- 作用：源码级调试

6、跟踪与性能调优工具
- 工具1：ulog（分级日志组件）
	- 作用：多级别、可插拔后端的运行时日志
- 工具2：SystemView / Tracealyzer 对接
	- 作用：任务/中断事件可视化

7、测试验证工具
- 工具1：utest（统一测试框架）
	- 作用：目标侧单元/集成测试

8、自动化 CI 工具
- 工具1：通用 CI（GitHub Actions / GitLab CI）+ SCons
	- 作用：流水线编排（无专属 CI 工具）

9、维护与 OTA 工具
- 工具1：`ota_downloader` / `http_ota` / `ymodem_ota`（分层 OTA 软件包）
	- 作用：从 HTTP/Ymodem 等来源下载固件并升级
- 工具2：RT-Thread 通用 bootloader
	- 作用：引导与升级

### 三、Zephyr

Zephyr介绍：Linux 基金会托管、Apache-2.0 的工业级 RTOS，工程化最完整——Kconfig + Devicetree + west + Twister + MCUboot 全链路自成体系；IoT/BLE/多平台场景首选（Nordic nRF Connect SDK 即基于它）。

1、选型评估工具
- 工具1：`west boards` / Supported Boards
	- 作用：枚举上游已验证的 SoC/板卡，判断目标板是否"已支持"

2、工程配置与代码生成工具
- 工具1：Kconfig（menuconfig / guiconfig）
	- 作用：依赖求解式功能裁剪，生成 `.config`
- 工具2：Devicetree（DTS + bindings + dtc）
	- 作用：把硬件拓扑从 C 代码解耦为声明式设备树（编译期生成）
- 工具3：`west manifest`（west.yml）
	- 作用：多仓库版本锁定，保证工程可复现
- 工具4：sysbuild
	- 作用：一个命令统一构建 App + MCUboot + TF-M 多镜像

3、编译构建工具
- 工具1：`west build` + CMake + Ninja + Zephyr SDK（sdk-ng）
	- 作用：多架构 GNU/LLVM 工具链 + 元构建 + 快速执行；SDK 内置定制 QEMU 与 OpenOCD

4、烧录下载工具
- 工具1：`west flash`（+ runners，抽象 OpenOCD/pyOCD/J-Link 等）
	- 作用：统一的多探针/多目标烧录入口
- 工具2：`west sign` + imgtool
	- 作用：生成签名镜像供 bootloader 校验（烧录即信任起点）

5、在线调试工具
- 工具1：`west debug` + GDB + OpenOCD / pyOCD / J-Link
	- 作用：统一调试入口，源码级断点/寄存器/内存调试

6、跟踪与性能调优工具
- 工具1：Zephyr tracing（基于 CTF 格式）
	- 作用：内核事件跟踪，供 Trace Compass/Perfetto 等分析
- 工具2：`ram_report` / `rom_report`
	- 作用：按段/符号静态统计 RAM/ROM 占用（裁剪与小型化依据）
- 工具3：Thread Analyzer
	- 作用：运行期线程栈使用 / CPU 占用统计
- 工具4：SystemView / Tracealyzer
	- 作用：第三方事件可视化

7、测试验证工具
- 工具1：Twister（`west twister`）
	- 作用：扫描/构建/运行测试矩阵（QEMU/native_sim/真板），输出 JUnit/twister.json
- 工具2：ztest
	- 作用：Zephyr 目标侧单元测试框架
- 工具3：pytest / Robot Framework / shell harness
	- 作用：外部框架驱动硬件交互测试
- 工具4：QEMU / native_sim / babbleSim（BLE 链路级）
	- 作用：无硬件仿真跑自动化测试

8、自动化 CI 工具
- 工具1：GitHub Actions + Twister in CI
	- 作用：全量板卡/配置测试矩阵回归
- 工具2：Zephyr Docker 镜像
	- 作用：提供可复现构建环境
- 工具3：Renode in CI / Arm Virtual Hardware（AVH）
	- 作用：无硬件 CI 测试 / 云端 FVP 仿真跑 CI

9、维护与 OTA 工具
- 工具1：MCUboot + imgtool
	- 作用：安全 bootloader：镜像签名校验、A/B 升级、失败回滚
- 工具2：mcumgr（SMP over BLE/UART/UDP）
	- 作用：设备管理与固件升级（手机/主机端可配合 nRF Connect Device Manager）
- 工具3：TF-M（Trusted Firmware-M）
	- 作用：Arm 安全世界安全启动/隔离固件

### 四、ThreadX

ThreadX介绍：Eclipse ThreadX（原 Azure RTOS），MIT 开源；picokernel 抢占式内核（支持 SMP）+ FileX/NetX Duo/USBX/GUIX 成套中间件，多项安全预认证，常用于功能安全场景；经 ST/NXP/Renesas/Microchip 原厂 SDK 分发。

1、选型评估工具
- 工具1：ThreadX 内核 + FileX / NetX Duo / USBX / GUIX 中间件套件
	- 作用：抢占式内核 + 中间件齐全 + 安全认证完备，支撑功能安全/认证场景选型
- 工具2：`ports/` 架构列表
	- 作用：确认目标架构支持情况

2、工程配置与代码生成工具
- 工具1：`tx_user.h` + `tx_initialize_low_level`
	- 作用：头文件宏裁剪内核 + 端口底层初始化（时钟/中断/内存）；以源码集成为主，无官方图形配置器
- 工具2：原厂 SDK 集成（ST X-CUBE-AZRTOS / NXP / Renesas / Microchip）
	- 作用：原厂图形配置 + 生成含 ThreadX 的工程

3、编译构建工具
- 工具1：CMake `add_subdirectory()`
	- 作用：把 ThreadX 作为子项目集成构建
- 工具2：原厂 SDK / IDE（CCStudio + TI Arm Clang 等）
	- 作用：随原厂工具链集成构建

4、烧录下载工具
- 工具1：调试探针（J-Link / OpenOCD）/ 原厂烧录工具
	- 作用：写入镜像（无专属烧录工具）

5、在线调试工具
- 工具1：原厂 IDE 调试 + RTOS 感知
	- 作用：查看内核对象与线程状态

6、跟踪与性能调优工具
- 工具1：TraceX
	- 作用：主机端记录并图形化分析 ThreadX 事件（中断/上下文切换时间线）；已随 Eclipse ThreadX 开源（MIT），安装包经 aka.ms/azrtos-tracex-installer 及 Microsoft Store 分发（2026-09 联网核实）

7、测试验证工具
- 工具1：通用框架（Unity / CMock 等）
	- 作用：单元/集成测试（无专属测试框架）

8、自动化 CI 工具
- 工具1：通用 CI（GitHub Actions 等）
	- 作用：流水线编排（无专属 CI 工具）

9、维护与 OTA 工具
- 工具1：原厂 bootloader / 安全启动组件
	- 作用：固件升级与安全引导

### 五、OpenVela

OpenVela介绍：小米开源、基于 Apache NuttX 的 IoT RTOS（github.com/open-vela），POSIX 风格；支持 arm/riscv/xtensa/tricore 多架构，配套 A/B OTA、XTS 认证体系与 QEMU 模拟器。

1、选型评估工具
- 工具1：`repo` + manifests（`openvela.xml`）
	- 作用：多仓拉取源码与预编译工具链；官方"支持矩阵"的来源
- 工具2：官方板卡 / XTS 认证清单
	- 作用：查已适配板卡与认证状态，判断是否需自研 BSP

2、工程配置与代码生成工具
- 工具1：Kconfig（menuconfig，kconfig-frontends）
	- 作用：板级配置裁剪，可复现
- 工具2：`vendor_template`（BSP 模板）
	- 作用：快速起 `chips/<chip>` + `boards/<chip>/<board>` 移植骨架
- 工具3：`tools/configure.sh`
	- 作用：由板级 defconfig 生成 `.config`

3、编译构建工具
- 工具1：`./build.sh`（Make，可 `--cmake` 切 CMake+Ninja）
	- 作用：顶层编译入口，产物 `nuttx.bin` 等
- 工具2：预编译工具链（arm-none-eabi / aarch64-none-elf / riscv-none-elf / xtensa / tricore）
	- 作用：官方多架构交叉工具链
- 工具3：ccache / bear
	- 作用：编译缓存加速 / 生成 compile_commands.json（供 clangd/IDE）
- 工具4：`genromfs` + `xxd`（mkromfs.sh）
	- 作用：生成 /etc ROMFS 镜像（rcS 启动脚本、密钥）嵌入固件

4、烧录下载工具
- 工具1：`make flash` + esptool（ESP32-S3）
	- 作用：串口烧录
- 工具2：厂商下载器（STM32CubeProgrammer / JLinkExe+`loadfile` / AURIXFlasher）
	- 作用：分别用于 STM32、J-Link SWD、英飞凌 TC4x 多核镜像烧录
- 工具3：minicom
	- 作用：串口终端，烧录后确认启动

5、在线调试工具
- 工具1：GDB + `pynuttx` GDB 插件（gdbinit.py）
	- 作用：系统语义级调试——`info nxthreads`、`memdump/memleak/memfrag/kasan`、`deadlock`、`crash busyloop`、`nxgcore` 等
- 工具2：`JLinkGDBServer` + `jlink-nuttx.so`
	- 作用：J-Link GDB Server + NuttX RTOS 感知插件（支持 `info threads`/线程切换）
- 工具3：Vela Emulator（QEMU，`emulator.sh`）
	- 作用：内置 gdbstub，无硬件做"JTAG 式"调试
- 工具4：GDB Stub（`CONFIG_LIB_GDBSTUB`）
	- 作用：无探针时经 UART/USB/网络做寄存器/内存/断点级调试，Crash 后自动接入

6、跟踪与性能调优工具
- 工具1：`trace`（sched_note）+ `traceparse.py` → Perfetto
	- 作用：内核打点（任务/中断/系统调用/锁事件）导出并时间线可视化
- 工具2：`perf`（PMU 采样）+ FlameGraph / `gprof`
	- 作用：函数热点剖析与火焰图
- 工具3：`critmon` / `irqinfo` / `cpuload` / `top`
	- 作用：临界区（关中断/关调度）、中断风暴、CPU 占用监控，识别实时性风险
- 工具4：CoreMark / Dhrystone / CacheSpeed / RAMSpeed
	- 作用：硬件性能基线测试

7、测试验证工具
- 工具1：`open-vela/tests`（testcases / testsuites）
	- 作用：官方用例集（异常/文件/图形/多媒体/调度/SMP/uORB/KV/安全/Flash 等）
- 工具2：CMocka（`CONFIG_TESTING_CMOCKA`）
	- 作用：C 单元测试框架（`cmocka -l/-t` 列用例/运行）
- 工具3：XTS 精简用例集（`openvela_xts_test_cases`）
	- 作用：厂商准入/自测标准（通用必测 + 品类选测）
- 工具4：`fstest` / `memstress` / `opus_ramtest` + tests/scripts（pytest + pexpect）
	- 作用：文件系统/内存压力测试 + 真板自动化测试

8、自动化 CI 工具
- 工具1：`public-actions`
	- 作用：官方可复用 GitHub Actions 集合（checkpatch/ci/docs 统一门禁、水印/中文检测）
- 工具2：`tests/cibuild.sh` + `nxstyle` / `cmake-format` / `config_check`
	- 作用：CI 构建依赖准备与风格/格式/配置检查

9、维护与 OTA 工具
- 工具1：`bootctl`（frameworks/system/ota）
	- 作用：A/B 分区升级管理（KVDB 记录 slot active/bootable/successful，bootloader 自动选分区与回滚）
- 工具2：`gen_ota_zip.py` + `ddelta`
	- 作用：全量/差分 OTA 包生成
- 工具3：`avb_verify` / `zip_verify` + `avb_sign.sh`
	- 作用：AVB/包签名校验与启动校验（防回滚）
- 工具4：`crashlog` / `coredump` / `nxgcore` / `resetcause`
	- 作用：崩溃日志、内核转储、复位原因等运维观测

## 嵌入式Linux工具

嵌入式Linux介绍：面向 MPU/AP（Cortex-A、RISC-V 应用核），适配核心是"BSP 层集成"——Bootloader + 内核 + rootfs + 设备树；本质是"造一个发行版"而非"编一个工程"。上游（配置/构建/烧写）与 RTOS 差异最大，下游（调试/trace/测试/CI/OTA）高度趋同。

1、选型评估工具
- 工具1：Linux 主线 SoC DTS（`arch/*/boot/dts`）
	- 作用：判断目标 SoC 是否有上游内核与设备树支持，决定"主线上游 vs 厂商 BSP"路线
- 工具2：Bootlin Elixir（在线交叉索引）
	- 作用：在线检索内核/U-Boot/DT 源码，快速确认驱动与 dts 支持现状
- 工具3：U-Boot `configs/` 与 `doc/board`
	- 作用：查目标板是否已有 U-Boot defconfig/板级支持
- 工具4：OpenEmbedded Layer Index
	- 作用：检索各 Yocto/OE BSP layer 的版本/配方/兼容性，选择 BSP 层
- 工具5：OpenWrt Table of Hardware（ToH）
	- 作用：查设备社区支持状态与可刷固件
- 工具6：KernelCI / LKFT 仪表盘
	- 作用：查看上游内核在目标平台的功能/稳定性健康度

2、工程配置与代码生成工具
- 工具1：DTC（Device Tree Compiler）
	- 作用：把 `.dts/.dtsi` 硬件描述编译为内核可解析的 `.dtb`（可反编译、overlay）
- 工具2：dt-schema（`dt-validate`）
	- 作用：依 YAML binding 校验 dts 合法性，把硬件描述错误提前到构建期
- 工具3：内核 Kconfig（menuconfig / defconfig）
	- 作用：生成 `.config`，选择 SoC/驱动/机型号
- 工具4：U-Boot Kconfig / defconfig
	- 作用：配置启动链（SPL/TPL、DDR、启动介质）
- 工具5：BitBake + OE metadata（recipe / `.bbappend`）
	- 作用：以配方元数据描述"怎么构建"，生成构建任务图
- 工具6：Yocto `devtool` / `kas`（YAML）
	- 作用：快速生成/修改 recipe；用单个 YAML 固化 layer/repo/distro 实现可复现配置
- 工具7：Buildroot / PTXdist / OpenWrt menuconfig
	- 作用：Kconfig 交互式配置目标平台、工具链、包集合
- 工具8：`repo`（git-repo manifest XML）
	- 作用：聚合多仓库，生成厂商 SDK 源码工程
- 工具9：原厂 Config Tools（NXP i.MX Pinmux/DDR/SerDes、STM32CubeMX for MPU、TI SysConfig）
	- 作用：图形生成引脚与 DDR 配置及 dts 片段

3、编译构建工具
- 工具1：Yocto/BitBake + OpenEmbedded-Core（Poky）
	- 作用：按依赖图调度编译/打包任务，从源码构建完全定制的发行版与镜像（长期演进/多产品线首选）
- 工具2：Buildroot
	- 作用：Make+Kconfig 轻量一体化构建，输出 rootfs+工具链+bootloader+内核（固化单一产品首选）
- 工具3：PTXdist / OpenWrt Buildroot
	- 作用：面向 BSP / 网络设备的构建系统
- 工具4：Kbuild（内核 `make`）
	- 作用：编译内核镜像、模块与 dtb
- 工具5：Yocto SDK（`populate_sdk`）/ crosstool-NG
	- 作用：生成可分发交叉 SDK（工具链+sysroot）/ 构建独立交叉工具链（glibc/musl）
- 工具6：ccache / distcc / sstate-cache + hash equivalence
	- 作用：增量/分布式加速；复用已构建产物
- 工具7：厂商 BSP 构建入口（meta-imx、TI Processor SDK、ST OpenSTLinux、meta-renesas、PetaLinux(AMD/Xilinx)、Rockchip SDK）
	- 作用：厂商封装的 U-Boot/内核/rootfs 构建，优先复用可大幅缩短 bring-up

4、烧录下载工具
- 工具1：`uuu`/mfgtools（NXP）、`rkdeveloptool`（Rockchip）、`snagboot`（通用）

- 工具4：`dd` / balenaEtcher
	- 作用：原始块写入 / 图形化写卡（通用兜底）
- 工具5：`flashrom`
	- 作用：读写 SPI NOR flash（含板载固件）
- 工具6：U-Boot `ums`/`fastboot`/`tftp`/`dfu`
	- 作用：设备侧接收镜像并写入存储介质
- 工具7：TF-A / OP-TEE / SPL 镜像
	- 作用：启动链各级"被烧录对象"（BootROM → SPL → TF-A → U-Boot → Kernel）

5、在线调试工具

## 附二：LiteOS 工具链建设方向（要点摘录）

OpenHarmony LiteOS（-M 轻量 / -A 小型）工具链竞争力方案的核心结论：**不造专用 IDE**，走「通用 IDE 插件化 + 双构建后端 + Windows 优先」路线——

- IDE 策略：VS Code 插件为主战场（P0），Keil/IAR 走"一键生成原生工程 + 构建钩子"（P0），Eclipse 可选，独立 Studio 不做
- 构建系统：GN/Ninja 为主力（鸿蒙标准化），Makefile 为轻量化兜底（单内核/教学/无 hb 场景）；一套构建语义 + 两个执行后端
- Windows 支持：LiteOS-M 优先 Windows 原生构建；LiteOS-A 原生能做的部分 + 一键 WSL/容器
- 竞争力指标："纯净 Windows 30 分钟从零到点灯"、"FreeRTOS/RT-Thread 一天迁移"
