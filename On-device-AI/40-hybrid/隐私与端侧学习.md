# 隐私与端侧学习

> 2026-10-23 初稿。收官篇：端侧 AI 的"为什么"——隐私不只是合规约束，更是端侧架构的出发点（Apple PCC、联邦学习、端侧微调、差分隐私）。
> 相关：[[Hybrid AI架构]]、[[端侧RAG与个性化记忆]]、[[手机SoC端侧AI能力横向对比]]

## 0. TL;DR

- **Apple Private Cloud Compute（PCC）是"隐私即架构"的标杆**：无状态计算、端到端加密（负载均衡器都解不开）、target diffusion 防定向路由、可验证透明（安全研究者可审计）——把"连 Apple 自己都看不到"做成了技术强制而非承诺
- **端侧学习的技术栈正在成型**：端侧 LoRA 训练（天玑 NPU 890 首发）+ 联邦学习（Apple 十年生产经验）+ 差分隐私（DP-SGD 用户级）——"数据不出端"与"模型持续进化"不再互斥
- Apple PFL 生产案例的关键数字：高资源预算下 **PFL 训练精度 0.852 vs 集中式 0.856**（ϵ=2.0）——隐私的精度代价在生产上可接受
- 分层结论：**推理隐私靠端侧/PCC，个性化靠端侧 LoRA/记忆，群体改进靠 FL+DP**——三层各有其技术，不能互相替代

## 1. Private Cloud Compute：隐私即架构

（[Apple Security Research: PCC](https://security.apple.com/blog/private-cloud-compute/)）

### 1.1 设计要求（原文四条）

1. **无状态计算**：个人数据只用于完成本次请求，不留任何痕迹（含日志/调试）
2. **可强制执行的保证**：安全性质完全由可分析的技术组件保证——不依赖 TLS 终结的负载均衡器这类"无法推理行为"的外部组件
3. **不设特权访问**：即使拥有生产系统管理权限的 Apple 员工也无法触达用户数据
4. **可验证透明**：研究界可审查

### 1.2 关键机制

- **计算节点**：定制 Apple 服务器芯片 + iOS 级安全技术（Secure Enclave、Secure Boot）+ 加固的 iOS/macOS 子集（去掉了远程 shell、系统自省等运维组件）+ Swift on Server 的 ML 栈
- **端到端加密到节点**：设备先验证节点公钥证书，直接加密到**节点子集**（而非"PCC 服务"整体）——负载均衡器和隐私网关在信任边界外、无密钥
- **target diffusion**：请求元数据不含个人标识；单次凭证用 RSA 盲签名（授权但不关联用户）；经第三方 OHTTP 中继隐藏源 IP；节点子集由无可偏置信息的负载均衡器选择且统计可审计——防御"把特定用户路由到被控节点"的定向攻击
- 学术分析见 [ACM 综述](https://dl.acm.org/doi/epdf/10.1145/3765613.3811691)

**与 [[Hybrid AI架构]] 的关系**：PCC 使 Apple 的路由判据极简——隐私敏感请求只有两个合法去处（端侧或 PCC），不存在"灰色的第三方云"。

## 2. 端侧学习：三个层次的技术

### 2.1 端侧微调（On-Device Fine-Tuning）

- **硬件里程碑**：MediaTek NPU 890 宣称首个支持手机端 LoRA 训练（天玑 9400 起）——个性化从"RAG/记忆"扩展到"权重"
- **Apple 的系统化用法**：端侧 3B 模型 + 任务适配器热切换（App 各带 LoRA，系统统一调度）——微调的不是"用户数据"而是"任务能力"，规避了隐私争议（见 [[SLM设计演进]]）
- 学术线：DP-DyLoRA（动态低秩 + 差分隐私）、FedP2EFT（跨设备 PEFT 结构选择）——核心矛盾是**小数据过拟合 + 训练开销**

### 2.2 联邦学习（FL）：Apple 的生产视角

（[Apple PFL 真实案例 arXiv:2502.04565](https://arxiv.org/pdf/2502.04565)，App 选择模型；[联邦个性化基础设施](https://machinelearning.apple.com/research/federated-personalization)）

- Apple 已在生产运行 FL 多年（评估、调优、深度学习三类任务），配套开源 [pfl-research](https://github.com/apple/pfl-research) 模拟框架
- 关键工程事实：
  - **离线模拟先行**：大规模超参/隐私参数调优在模拟中完成，再上真机
  - **从 checkpoint 微调 > 从头训练**：冻结主干只训子集，适应分布漂移
  - **PFL 精度代价可控**：高资源预算（1 万设备/迭代 × 500 迭代）下 0.852 vs 集中式 0.856；低预算（0.63 遍数据）明显回退——**资源预算决定可行性**
- DP + FL 是标配组合：FL 只保证"原始数据不出端"，模型更新本身可被攻击反演——必须叠加差分隐私

### 2.3 差分隐私（DP）

- **云侧**：Google 展示了用户级 DP 微调 LLM 的可行性（ELS/ULS 两种 DP-SGD 变体的贡献界自动设定，[研究博客](https://research.google/blog/fine-tuning-llms-with-user-level-differential-privacy/)）——严格定义下微调仍优于仅用预训练模型
- **端侧**：Apple 的 DP 用于遥测/个性化数据聚合（本地化 DP 传统强项）；研究线 DP-FedLoRA 把 DP 噪声只加在 LoRA 更新上，降低精度损失
- 共同教训：**DP 的噪声预算与模型规模/训练轮数的分配是精细工程**，拍脑袋定 ϵ 会毁掉模型

## 3. 隐私技术的分层地图

| 目标 | 技术 | 成熟度 |
|---|---|---|
| 推理隐私（数据不出域） | 端侧推理 / PCC | ✅ 产品化 |
| 检索隐私（个人语料） | 端侧 RAG（见 [[端侧RAG与个性化记忆]]） | ✅ 产品化 |
| 个性化（风格/偏好） | 端侧 LoRA / 记忆注入 | 🟡 天玑硬件就绪，生态早期 |
| 群体改进（跨用户学习） | FL + DP | 🟡 生产可用（Apple），LLM 级早期 |
| 云端可信任 | PCC / 机密计算 / 可验证审计 | 🟡 Apple 独苗 + 学术跟进 |

注意一个不对称：**推理侧隐私已产品化，训练侧隐私仍在研究**——端侧大模型的"学习闭环"（用户用了 → 模型变好 → 仍保隐私）是最大的未完成工程。

## 4. 关键洞察

1. **隐私的工程范式是"减少信任面"而非"增加加密"**：PCC 的每个设计（无状态、节点子集加密、盲签名）都在缩小"必须被信任的组件集合"——可分析性先于密码学
2. **端侧学习的真正瓶颈不是算法而是资源调度**：Apple 案例里"每轮设备数 × 轮数"的预算思维，与 [[异构调度与NPU利用]] 的计算调度是同一类问题——设备是稀缺、异构、自愿参与的
3. **LoRA 是端侧学习的"隐私天然单元"**：小（MB 级）、可丢弃、可审计、可叠加 DP——比全参更新更适合"数据不出端"的约束；MoE 时代的对应物尚无定论
4. **"连厂商都看不到"正在成为高端 AI 产品的卖点而非成本**——PCC 出现后，隐私从合规底线变成了架构选型的竞争维度

## 5. 开放问题

- [ ] LLM 级联邦学习的规模化验证（目前生产案例都是小模型/分类器）
- [ ] PCC 模式的可复制性（需要垂直整合芯片+OS+云，护城河极深——其他厂商的对应物是什么？机密计算 TEE？）
- [ ] 端侧 KV cache / 向量库中用户数据的残留与遗忘（与 [[端侧RAG与个性化记忆]] 的开放问题呼应）
- [ ] DP 与个性化的根本张力：个人化程度越高、隐私保护越难（k=1 的"群体"）
