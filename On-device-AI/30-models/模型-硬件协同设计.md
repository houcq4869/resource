# 模型-硬件协同设计

> 2026-10-23 初稿。本笔记是 30-models 层的收官：把散落在各篇的"为端侧而生的架构"收拢成一个论点——
> **模型设计正在从"通用架构 + 部署期优化"转向"训练时就内嵌硬件约束"**。
> 相关：[[SLM设计演进]]、[[KV cache与长上下文]]、[[MoE端侧化]]、[[多模态端侧模型]]、[[异构调度与NPU利用]]

## 0. TL;DR

四类协同设计已经从论文走进产品：

1. **嵌套弹性**：MatFormer（Gemma 3n）——一个模型内嵌多个尺寸，运行时按设备状态选档
2. **KV cache 形态设计**：Apple 5:3 分块共享、GQA/MLA——在训练时决定内存第二增长曲线
3. **存储层级感知**：MobileLLM 的立即块共享（SRAM 容量）、MoE 的冷热分层（[[MoE端侧化]]）、Gemma 3n 的 PLE 外置（embedding 放本地存储）
4. **精度分层**：Apple 逐算子 bit 率（Talaria）+ LoRA 混合 2/4-bit；EdgeMoE 专家级 bitwidth

协同设计的判据：**该设计在通用硬件 benchmark 上不成立、只在真实端侧约束（SRAM/带宽/热/NPU 算子库）下才有收益**。

## 1. MatFormer：嵌套弹性（Google，NeurIPS 2024）

[MatFormer (arXiv:2310.07707)](https://arxiv.org/html/2310.07707)——"套娃 Transformer"：

- **机制**：FFN 隐层神经元按重要性排序，前 m₁ ⊂ m₂ ⊂ … ⊂ m_g 个神经元构成嵌套子模型（g=4 档，FFN ratio 0.5/1/2/4）；训练时联合优化多档
- **Mix'n'Match**：每层独立选档 → 组合出 g^l 个中间尺寸模型；850M 模型可抽取 582M–850M 全谱系，且**抽取的子模型优于同尺寸独立训练模型**
- **行为一致性红利**：子模型间输出高度一致 → **自己给自己当 draft 模型**做投机解码，天然规避外挂 draft 的内存税（与 [[投机解码与加速]] 直接衔接）

### Gemma 3n = MatFormer 的产品化

（[官方文档](https://ai.google.dev/gemma/docs/gemma-3n) / [开发者指南](https://developers.googleblog.com/introducing-gemma-3n-developer-guide/)）

- E4B 内嵌 E2B；预抽取的 E2B 推理快 2×；MatFormer Lab 工具可按硬件切片中间尺寸
- 路线图明确"弹性执行"：单一部署模型按设备负载**运行时切换 E4B/E2B 路径**——动态功耗管理下沉到了模型结构内部
- 配套的 **Per-Layer Embedding（PLE）**：把每层的 embedding 参数外置到本地存储按需缓存——权重不全部驻留内存

## 2. KV cache 形态：训练时决定内存曲线

（详见 [[KV cache与长上下文]] §5，此处只列协同设计视角）

| 设计 | 协同点 |
|---|---|
| GQA（事实标准） | KV 头数直接除 cache 体积，推理零成本 |
| **Apple 5:3 分块共享** | block2 复用 block1 末层 KV：-37.5% cache + TTFT 改善——专门为"端侧内存 + 首 token 延迟"设计（[Apple FM 2025](https://machinelearning.apple.com/research/apple-foundation-models-2025-updates)） |
| **Gemma 3n KV 共享** | 按 frac_shared_layers 配置跨层共享（HF 实现中 35 层仅 20 层不共享） | 
| MLA（DeepSeek） | 潜在向量缓存；递归展开结构对 NPU 静态图的适配仍在验证 |
| 滑窗/全局交替（Gemma 系） | cache 有硬上界——对"内存确定性"要求高的系统设计是刚性收益 |

## 3. 存储层级感知设计

端侧存储层级：**寄存器 → SRAM(~20MB) → DRAM(8–12GB) → UFS/本地存储(256GB+)**。协同设计 = 把参数按访问模式放进正确的层：

| 工作 | 层级决策 |
|---|---|
| MobileLLM-LS | 立即块共享让权重驻留 SRAM 两次计算，避免 SRAM↔DRAM 往返（[论文](https://arxiv.org/html/2402.14905v2)） |
| EdgeMoE | 热的非专家驻 DRAM、冷的专家放外存按需换入（[[MoE端侧化]]） |
| Gemma 3n PLE | per-layer embedding 缓存到本地存储；模态权重条件加载（纯文本不载视觉/音频） |
| Apple 2-bit | 压到 3.7bpw 的本质动机：让模型整体驻留 DRAM 成为可能 |

## 4. 精度分层设计

- **Apple Talaria**：交互式延迟/功耗分析工具，**逐算子选择 bit 率**——不同算子对量化的敏感度不同，混合 2/4-bit（均 3.7bpw）+ LoRA 适配器补偿
- **EdgeMoE 专家级 bitwidth 自适应**：量化鲁棒的专家压更低位——"精度预算"按专家分配
- 联系 [[量化技术]] §6：小模型 4-bit 脆弱 → 协同设计的答案是**精度预算的结构化分配**而非全局统一位宽

## 5. 判别一个设计是否"协同"的框架

```
真协同设计：
  ✓ 收益依赖具体硬件参数（SRAM 大小、带宽、算子库覆盖）
  ✓ 训练时就固定了部署形态（无法事后从基线模型改造）
  ✓ 在云端 benchmark（纯算力比较）上不占优甚至更差

伪协同（实为通用优化）：
  ✗ 任何硬件上都更快
  ✗ 可以作为插件加载到现有模型
```

按此框架：MatFormer 的 Mix'n'Match 是"弹性"而非单纯协同（通用收益），但其**运行时换挡**目标是端侧独有场景；Apple 5:3 分块、MobileLLM-LS 的 SRAM 决策、Gemma 3n 的 PLE 外置是强协同案例。

## 6. 关键洞察

1. **优化点从推理期向训练期迁移**：GGUF 量化、KV 量化、投机解码都还能"部署时再决定"；5:3 分块、MatFormer、PLE 一旦训练完成就不可逆——**端侧模型的设计自由度正在提前锁定**
2. **一致性成为一等公民**：MatFormer 子模型间、draft-target 间的行为一致性直接兑换成投机解码收益——"模型族内部对齐"是新设计目标
3. **NPU 约束开始反向塑造模型**：GEMV 不友好 → 激活稀疏（SPARC 0.95）；静态图偏好 → 递归/线性注意力重新被评估；ANE 的 KV 更新路径 → Apple 专门改 attention 结构
4. **尚未发生的**：真正的 NPU-aware NAS / 结构搜索在 LLM 时代基本缺位（CNN 时代的 MobileNet/MnasNet 有成熟方法论）——ACL survey 也把 model-hardware co-design 列为首要开放机会

## 7. 开放问题

- [ ] "弹性"的极限：Mix'n'Match 之外，注意力头/层数/词表的联合弹性
- [ ] 协同设计的可移植性：为 Hexagon 协同的模型换到 ANE/Ethos 上损失多少（跨 NPU 的"协同碎片化"）
- [ ] 训练期协同的成本模型：如何在不接触目标设备的情况下预测端侧收益（需可信的端侧性能模拟器）
- [ ] 线性注意力/SSM 的 NPU 实证：递归状态与静态图的匹配度假设尚缺系统验证
