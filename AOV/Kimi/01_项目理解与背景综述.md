# 01 项目理解与背景综述

## 1. 项目定位

在 OpenHarmony L1 小型系统（LiteOS-A 内核，small 形态）上，基于海思 IPC 平台实现 **AOV（Always-On Video）全天候持续录像**：

- **主平台**：hi3516dv300 / hispark_taurus（双核 Cortex-A7，SMP）
- **对照平台**：hi3518ev300 / hispark_aries（单核 UP，验证跨平台可移植性）
- **业务模式**："周期唤醒抓 1 帧、抓完即睡"的 1fps 值守录像（>95% 时间）+ AI/MD 命中切 15~30fps 全速录像，支撑电池类 IPC 7×24 不断录
- **双重目标**：① 产品侧实现低功耗 AOV；② 使分档锁、设备链表、时间补偿等机制具备回馈 OH 上游的价值

**核心命题**（综合版 TL;DR）：AOV 成立需系统层同时满足"睡得深（省电）、时间不丢（证据）、醒了时间准（可信）"，而 OH L1 恰在这三处"框架在、实现空"——内核 PM 三档默认 handler 同为 PRINTK+WFI、powermgr small 挂起循环是 `sleep(10)` 模拟桩、NTP 链路断且无开机 RTC 校时、深睡无时间 offset 补偿。

## 2. 量化指标

口径纪律：整板含 sensor、WiFi 保活、25℃、1fps 2MP；业界宣传值与实测差异可达 4~8 倍（海思 80mW 为营销口径，开发板整板实测深睡 350mW）。

| 指标 | 第一步·浅 AOV | 第二步·标准 AOV | 第三步·深睡 AOV |
|---|---|---|---|
| 值守功耗 | 建 WFI 级基线 | ≤80mW 保底 / ≤45mW 竞争 | ≤45mW 稳定 |
| STR 深睡功耗 | — | — | ≤40mW 保底 / ≤10mW 竞争 |
| 唤醒延迟 | ≤1s | ≤500ms | ≤250ms |
| 事件切换 | ≤2s | ≤1.5s | ≤1s |
| 冷启动 TTFF | 分段打点建基线 | ≤1.5s | ≤1s |
| 时间连续性 | 24h 误差 ≤1s | +NTP 周期校时 | 深睡 7 天误差 ≤1s |
| 续航（9000mAh） | — | ≥10 天 | ≥13 天 |
| 存储 | ≤1GB/天 | ≤600MB/天 | 同左 |

小型化实测（已完成）：rootfs+userfs 内容 53.9→24.6MB（**-54.4%**，10⁶ 口径）、rootfs -38.2%、userfs -77.2%（最大单项：无屏字体 17.3MB）、构建目标 8124→5129（-37%）、组件 50→30、init 服务 15→7。

## 3. 总体技术方案

### 3.1 五层架构

| 层 | 内容 |
|---|---|
| L5 业务策略层 | aov_policy 状态机（设计，无代码实体）+ aov_poc 单帧循环（已实现骨架）+ AI 检测 |
| L4 电源服务层 | powermgr_lite：RunningLock / Suspend 准入 / WakeSource API / battery |
| L3 内核层 | LiteOS-A PM 增强（K1~K5） |
| L2 驱动/平台层 | BSP SYSCTRL 注册（B1）、HDF 驱动 listener（B2）、DVFS（B4）、WiFi WoW（B5）、MD（B6）、MPP 电源（B7） |
| L1 硬件层 | RTC / GPIO / hi3881 / SD / CRG 电源域 / DDR self-refresh |

### 3.2 S0~S3 状态机（映射 LiteOS-A 四档）

- **S0 ACTIVE**（NORMAL 档）：15~30fps 全速录像/推流/AI，持 BACKGROUND 锁
- **S1 值守**（LIGHT 档）：单帧循环（唤醒→sensor restart→SNAP 单帧→编码→MD/AI→1MB 攒批落盘→sensor standby→回睡），目标 ≤80mW，唤醒窗口预算 ≤100ms
- **S2 STR**（DEEP 档）：长时无事件/低电量进入，DDR self-refresh + 电源域关断（🔒 第三步，依赖海思 NDA）
- **S3 软关机**（SHUTDOWN 档）：SoC 下电仅 WiFi 保活（当前内核禁用该档）

强约束：上传完成才可休眠；低电量降档/太阳能升档；看门狗防睡死；休眠入口 wakeup_count 竞态检查。

### 3.3 三步走路线

1. **第一步·浅 AOV**（树内闭环，✅ 代码已全落地）：K1~K5 + S1 + B1 + T1/T4/T5 + T6 三批裁剪。收益在链路打通+可计量，LIGHT 档当前=静默 WFI（真实时钟门控需 CRG 资料）。
2. **第二步·标准 AOV**（⏳ 未启动）：B2 驱动 listener / B4 DVFS / B5 WoW / B6 MD 接入 / MPP 模块级裁剪 / MMZ 重配 / G1 tickless / G4 RTC alarm，对标 ≤80mW。
3. **第三步·深睡 AOV**（🔒 NDA 硬阻塞）：B7 MPP deinit + 真实电源域序列 + 从核 park + SHUTDOWN 档。

## 4. K / S / B / T 编号体系

### K = 内核层改动（kernel/liteos_a）— 全部 ✅ 落地

| 编号 | 内容 | 机制 |
|---|---|---|
| K1 | 分档 PM 锁 | `lock[4]` 数组替代单计数器；档位 M 的锁否决 M 及更深档；被否决时**自动降级**而非放弃；新增 `LOS_PmLockRequestEx/TimeLockRequestEx`；修"录像持锁→永不休眠"死结 |
| K2 (T4b) | 时间 offset | `g_osPmTimeOffsetCycle` 注入 `OsGetCurrSchedTimeCycle`，tick/软定时器/gettimeofday 全链跨深睡连续；deep 钩子按 RTC 差值补偿 |
| K3 | 设备链表 | `pm->device` 单指针→双向链表 + 8 节点静态池；注册序 suspend/逆序 resume/失败精确回滚 |
| K4 | idle 自动挂起 | 覆写 WEAK `OsIdleTask`（whole-archive 生效），idle 无锁自动 `LOS_PmSuspend(0)`，失败退化裸 WFI；SMP 从核保持 WFI park |
| K5 | wakeCount 竞态 | `LOS_PmSuspend(wakeCount)` 启用被丢弃参数=锁计数快照，临界区内失效即放弃（Linux wakeup_count 语义）；附带 ReadLock 超时返回修复 |

## 5. 关键工程发现

1. **SMP 关闭被实证否决**：关 `LOSCFG_KERNEL_SMP` 后 spinlock 退化为 inline 空操作，海思 MPP 预编译库按 SMP=y 编译、1728+ 处 out-of-line 引用 spinlock 符号 → 链接失败。dv300 深睡只能走"从核 park"路线，除非海思提供 UP 编译 MPP 库。
2. **deep 档"三重空置"**：内核 WFI 占位 + 平台零 SYSCTRL 注册 + 服务假挂起，三层同时为空。
3. **`SDK_exit()` 树内存在**（sdk_exit.c:277，零调用者），B7 有实施基础。
4. **裁剪机制结论**："config.json 删除 ≠ 镜像删除"（GN 传递依赖），须五维反查（BUILD.gn/external_deps/头文件/samgr 服务名/init/hcs）；out/ staging 陈旧文件须 clean 重建。
5. **bundlems 200ms 轮询线程**为 AOV 敏感唤醒源（建议改事件驱动或 30s+，**后续文档漏项**）。
