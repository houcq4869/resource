### 需求背景

- 分析海思 IPC 项目业务，完成 L1 OH 非核心能力的裁剪，支撑 L1 OH 小型化目标

AOV（Always-On Video，全天候持续录像/全时录像）：**基于超低功耗内存（DDR self-refresh）的快速启动待机技术，实现电池 IPC 7×24 小时不间断录像**

##### 硬件功耗域设计

	上层（内核/服务/业务）做得再好，如果硬件不能真正关电，功耗就下不来，因此硬件功耗域是全部省电手段的物理地基。

功耗分为动态功耗（∝ C·V²·f，电路翻转产生，靠停表、降频降压来省）与静态功耗（通电即漏电，靠拉闸、关断电源域来省）。由此形成由浅入深的省电动作：时钟门控（停表，状态保留）→ 电源域关断（拉闸，状态丢失）→ 保持/自刷新（拉闸但保住必要状态）。

设计要点：

- 电源域与电源门控：能关尽量关，必须留的最小化；每个域支持工作、保持、关断三态。
- 电压调节与时钟树：非必要域降压或关断，系统总线时钟降到最低基准，由电源管理芯片与时钟复位寄存器控制。
- DDR 自刷新与接口保持：让内存自己刷新自己、控制器歇着，既省电又不丢数据；主控断电时由接口层保持信号状态，是深睡的地基。
- 低功耗岛/常开域：把"值守"与"处理"在硬件上分离，主控要么全速、要么全睡，避免中间态。
- sensor 低功耗与快启：待机功耗可低至微瓦级，重启时只写必要寄存器以缩短出图时间。

##### TTFF快速启动

	快启的目标不是"开机快"，而是"最短时间拿到稳定可用的图像"（TTFF）；TTFF 越短，占空比唤醒窗口越短，平均功耗越低。
	启动流水线：上电 → bootloader → kernel → rootfs/init/应用 → 首帧出图。

两类场景：冷启动（掉电重启，走完整流水线，靠裁剪与并行压缩耗时）与 STR 唤醒（内存现场保留，只需恢复时钟、电源域与外设驱动，配合 sensor 快启，可达百毫秒级）。现代方案以 STR 唤醒为主路径、冷启动为兜底。

分段优化手段：

- bootloader：裁剪引导程序、取消启动倒计时、跳过完整引导阶段、加载与 sensor 初始化并行。
- kernel：去除内核打印、裁剪无用驱动、镜像压缩、快出图驱动内建并提权、优化首帧的帧策略。
- rootfs/应用：以内存换时间、精简启动脚本、文件系统瘦身、主程序最先运行、非必要库延迟加载。
- sensor 侧：只写必要寄存器完成待机与重启，缓存曝光参数使唤醒单帧即正确曝光。

##### STR待机唤醒机制

	STR 把系统状态保存在内存中，DDR 进入自刷新，其余电源域尽量关断，由常驻单元监听唤醒源；唤醒后恢复现场继续执行，无需重新 boot。

机制可拆为四件事：状态保存（CPU 寄存器与设备上下文存入内存或保持）、内存保数据（DDR 自刷新）、其余断电（电源域关断与时钟树修剪）、常驻听唤醒（常开域监听唤醒源，唤醒后逆序恢复现场）。

软件流程上，Linux 以六阶段完成挂起（设备准备 → 主挂起 → 晚挂起 → 关中断挂起 → 系统核心挂起 → 平台进入硬件休眠），唤醒严格逆序；核心规则是"越底层越晚睡、越早醒"。四类配套机制：

- 唤醒锁：上层持锁表示系统仍需运行，无锁时才允许休眠。
- 唤醒计数：入睡前核对计数快照，计数变化则放弃本轮休眠，避免丢唤醒事件。
- 驻留判据：空闲时长需大于"最小驻留时间 + 退出延迟"，才值得进入深睡。
- 忙保护：正在写卡或 flash 时禁止挂起，避免数据不一致。

唤醒源必须挂在常开域上；并非所有外设、在所有状态下都能作唤醒源，唤醒后还需恢复中断控制器状态。主要唤醒源包括 RTC 定时、GPIO/PIR、WiFi 远程唤醒、声音触发、AI 事件与独立 MCU。

AOV 特有形态是"单帧 suspend-resume 循环"：每个占空比周期完整走一遍挂起—唤醒—恢复，但每轮只处理一帧。

##### 占空比录像策略

	核心逻辑：主控绝大多数时间休眠，仅在需要时短暂唤醒执行必要任务，完成后立即重新休眠。一个周期为"定时唤醒 → 快速取帧与编码 → 可选任务 → 立即休眠"。
	平均功耗 P_avg ≈ P_sleep + (P_wake − P_sleep) × duty，唤醒后工作时间越短，平均功耗越低。

设计要点：

- 单帧模式：每轮只处理一帧，处理完即让 sensor 待机。
- 进出 AOV 的收尾：取完剩余帧、关闭非必要媒体流、卸载外设驱动，退出时逆序恢复。
- 检测—决策—唤醒下沉小核：主核休眠时由协处理器独立完成检测与唤醒决策。
- 滞回切换：值守检测到目标切全速录像，连续若干帧无目标再退回值守。

##### 存储与网络链路省电

	主控睡了，SD 卡与 WiFi 芯片自身仍在耗电；醒来前后的写卡与联网若处理不当，会抵消前面的省电。

存储侧：

- SD 三级省电：空闲 → 时钟门控 → 断电，按使用频率选档；断电与上电有严格时序要求。
- 攒批写入：帧先在内存攒批，满批或事件时才落盘，减少写卡唤醒次数。
- 休眠前同步并卸载 SD 驱动；写入期间禁止系统休眠。
- 分段文件与掉电安全：按时间分段、保证每段可独立回放。

网络侧：

- WiFi 按 DTIM/listen interval 把延迟换功耗；主控深睡时由 WiFi 芯片或 MCU 维持连接与心跳，收到指令再唤醒主控。
- 事件"上传完成才可休眠"是硬约束。

##### 功耗状态机设计

	功耗状态机是上述技术的集成框架：每级状态对应一组"保持什么、关掉什么、谁能唤醒、唤醒多快"的契约。业界收敛为四级：Active（全速）→ AOV 值守 → STR 深睡 → 保活/软关机。

典型实现：

- 瑞芯微 RV1126B 三模式：正常帧率 / AOV 低帧率 / 低功耗保活，按任务负载与电量自动切换。
- 君正 Atlas 大小核：小核常驻负责低帧率采集与检测唤醒，大核与高清通路深度休眠。

状态切换条件：事件（AI/PIR/音频）升档、连续无目标降档、RTC 定时维持值守、电量阈值强制降档、太阳能输入升档；并遵循"上传完成才可休眠"的强约束。

##### RTOS层低功耗框架

	低功耗框架由四件套构成：tickless、唤醒锁、动态调频、驱动电源管理。

- tickless：空闲期停掉周期节拍，让系统长睡，醒来用低功耗定时器补偿计数。
- 唤醒锁：按休眠模式加锁（持锁不进入该模式），支持超时自动释放。
- 动态调频：短时唤醒窗口全速冲刺、空闲降频，且与唤醒锁互锁（有锁不降频）。
- 驱动电源管理：设备注册挂起/恢复回调，按"越底层越晚睡越早醒"的顺序执行。

### 需求分析总结

AOV 成立需要系统层同时满足三点：**睡得深（才省电）、时间不丢（才是证据）、醒了时间准（才可信）**。业界以"五层技术栈 + 功耗状态机"实现：底座是硬件功耗域与 STR，其上由占空比策略与存储/网络省电支撑，横切面依赖 tickless、唤醒锁、动态调频与驱动电源管理。

对照可见，AOV 的核心不在业务功能，而在系统层的低功耗地基与时间连续性。因此本项目的重心是：在 OpenHarmony L1 上补齐系统层的休眠链路、唤醒准入、时间补偿与设备有序挂起能力，同时通过非核心能力裁剪减小体积、缩短启动、收敛常驻任务。

## 方案设计

**设计目标：**
	在不破坏录像、AI、存储、OTA 等核心链路的前提下，为 OpenHarmony L1 补齐 AOV 所需的系统层低功耗与时间连续性能力；
	通过非核心能力裁剪减小体积、缩短启动、收敛常驻任务；沉淀的通用机制（分档锁、设备电源链、时间补偿等）具备回馈上游的价值。

### OpenHarmony L1能力分析

**能力分析：**
	结合 OH L1 当前能力，分析实现 AOV 的系统层修改方案；
	盘点内核层、组件层、驱动层及平台层缺口，建立系统能力差距清单。

#### 内核层

	目前框架全在（状态机、时序、锁、竞态保护），但省电执行（tickless、分档、时间补偿、自动进入）全空。

- **功耗状态机与档位模型**：四档枚举与系统控制回调框架完整，但浅睡、深睡等档位默认指向同一处理函数，档位间行为无差异，软关机档不可用。
- **挂起/恢复主流程**：时序骨架与失败回滚完整，但收尾回调在自旋锁临界区内执行，且回调执行上下文无约定，存在隐患。
- **PM 锁（休眠准入）**：支持命名锁与超时自动释放，但为全局一票否决——任一锁存在即所有档都无法休眠，无法表达"允许浅睡、禁止深睡"。
- **设备注册链**：仅支持单设备注册，后注册覆盖前者，无顺序与回滚能力。
- **节拍与时间基座**：节拍停/启为空实现（节拍不会为长睡而停），系统时间直接取硬件计数、无补偿，深睡断电即丢时间。
- **空闲自动进入**：空闲任务仅等待中断，未接入电源管理，系统无法自动休眠；唯一触发入口为只读的 proc 节点。
- **唤醒与竞态**：具备唤醒标记与入睡前二次检查，但唤醒计数参数被丢弃，且唤醒源硬件链路未接入电源管理。

#### 组件层

	电源与电池服务以服务框架形式就绪，链路部分贯通，但关键实现为桩。

- **服务框架**：以服务管理框架注册电源与电池服务，接口齐全，但仅作"翻译层"，实际动作落到 proc 节点与内核。
- **运行锁链路**：从业务加锁到内核 PM 锁的链路真实贯通，同类锁以引用计数管理，首个加锁才通知内核、最后一个释放才解除；但加锁失败不上报，且未按名字维护映射。
- **挂起/唤醒服务接口**：接口与原因枚举齐全，但立即挂起参数被忽略、无权限校验，"加锁即唤醒"标志无人消费。
- **自动挂起循环**：小型形态为 sleep 假桩，不触发真实挂起，还制造周期无效唤醒。
- **挂起准入**：默认持"唤醒保持"锁、显式放行，配合阻塞计数，骨架可用；但检查为轮询。
- **电池服务**：接口齐全但数据源硬编码，无法接入真实电量。
- **唤醒源管理**：缺失配置 RTC/GPIO/WiFi 唤醒的接口。

#### 驱动层

	驱动电源管理框架完整（桥接、回调、广播、顺序），但真正实现回调的外设极少。

- **内核桥接**：HDF 以"设备"形式注册到内核电源管理，内核挂起时经它广播到各驱动，失败自动回滚。
- **驱动回调接口**：驱动通过注册电源监听器声明挂起/恢复回调（含打盹态），但需显式注册，每个设备节点仅支持一个监听器。
- **状态广播链**：从管理服务经设备主机逐层广播到驱动，挂起为逆序、恢复为正序；单个设备失败只记日志、不阻断。
- **外设实现现状**：仅触摸、音频、显示等少数驱动实现回调，存储、时钟、网络等均未挂接，设备级省电尚未落地。

#### 平台层

	平台层是"内核发令"与"芯片真正关电"之间的接线层，当前几乎为空，是最大缺口。

- **系统控制注册**：内核预留的平台电源钩子无人注册，休眠只能落到默认的空转等待。
- **电源域/时钟/内存**：运行时的电源域关断、时钟门控、DDR 自刷新均无实现（DDR 自刷新代码仅存在于引导阶段的训练流程）。
- **空闲任务覆写**：无平台覆写，空闲任务不会进入电源管理。
- **动态调频**：调频寄存器地址已定义但未使用，总线频率为硬编码，且缺寄存器位域资料。
- **媒体处理库**：全为预编译库，无法在其内部做电源钩子，深睡只能整体去初始化再重启；模块级退出函数存在但无调用者。
- **引导程序**：仅有预编译产物，启动链树内不可优化。

### 小型化方案设计

**核心内容：**
	以设备真实用途为锚点，先由值守期最小必需集确定下限，再自顶向下对组件、服务启动、媒体模块、内核驱动四层裁剪：值守最小集常驻、事件能力延迟加载、维护能力按需拉起、其余直接裁剪；每个候选经五维依赖反查后分级处置，裁不动者转保留，删减缺口显式移交产品化。

**裁剪方案：**
	将 AOV 划分为三个工作期（值守期、事件期、维护期）；
	按"**值守期最小集常驻、事件期能力延迟加载、维护期能力按需拉起、其余直接裁剪**"的原则进行。

#### 设计目标与约束

小型化的目标是在不破坏核心链路的前提下，减小镜像与分区内容体积、降低启动负担与常驻任务数。它与低功耗是一体两面：体积更小意味着加载更快、内存水位更低、空闲更干净，因此以内容体积、启动服务数、构建目标数作为衡量维度。

三项约束贯穿始终：

- 业务不能坏：录像、AI、存储、OTA 等核心链路及其公共接口依赖必须保留；
- 构建存在耦合：删除顶层配置不等于删除产物，依赖会经多种路径把组件重新拉回来；
- 闭源与公共仓边界：芯片预编译库不可改，公共组件仓的改动会影响其它产品形态。

#### 业务锚点：三个工作期

裁剪以设备真实用途为锚点——先定义"设备怎么用"，再决定"要留什么"。AOV 分为三个工作期：

- 值守期（时间占比最高）：周期唤醒抓帧、检测、攒批落盘、回睡，只需要最小必需集；
- 事件期：命中后全速录像、抓拍与上传，在值守集之上增加编码、抓拍与大缓冲能力；
- 维护期：联网预览、升级与配置，能力按需拉起。

值守期最小必需集由采集编码链、检测链、存储链、时间链、电源链与时间戳叠加构成，是裁剪的"下限"。

#### 裁剪方法

自顶向下分四层推进，每层决策对象不同，越往下越接近物理收益、也越难改动：

- 组件级：顶层部件清单，决定哪些组件被编译进产品；
- 服务启动级：开机服务列表，决定哪些服务常驻、哪些延迟或移除；
- 媒体模块级：预编译库清单，决定链接进内核的媒体模块集合；
- 内核驱动级：内核配置与设备配置，决定驱动与设备的取舍。

对每个候选组件按四类处置：常驻（核心链路必需）、延迟加载（启动不需要但运行可能用）、按需拉起（特定场景才用）、裁剪（形态不需要且依赖可断）。

需说明的是，裁剪不仅涉及产品配置，个别公共组件的构建元数据也需同步调整（含清理异常声明、摘除随裁件残留的死代码条目），并顺带修复少量上游缺陷。

#### 依赖反查

裁剪不能只看配置清单，必须做依赖反查，逐一确认"能否安全断开"。反查覆盖五个维度：

- 构建路径依赖：保留组件的构建文件直接依赖被裁目录中的目标时，该目标仍会被编译；
- 组件名依赖：以"组件名"形式声明的依赖要求组件仍在产品清单内，否则构建直接失败；
- 头文件引用：被裁组件的头文件若被保留组件包含，编译无法通过；
- 服务名引用：运行时经服务管理框架按名字取服务，缺失会导致服务注册失败；
- 启动与设备配置：启动脚本与设备配置中的残留条目会造成加载失败噪声。

任一维度命中，都可能"裁而不减"甚至构建报错。反查结论决定每个候选的最终处置，并据此排定实施顺序。

#### 分层裁剪

**组件级**：以形态标签快速粗筛，把候选分为"明显该裁、明显该留、需要核查"三堆；明显该裁的按下节归并，明显该留的是核心链路，需要核查的进入依赖反查。

**服务启动级**：将开机服务分为关键路径、延迟组与裁剪组；关键路径优先拉起，延迟组在首帧达成后或按需启动，裁剪组随组件移除。

**媒体模块级**：预编译媒体库按值守、事件、无场景三档取舍；值守期只保留必需模块，事件期模块延迟初始化，无场景模块不链接。

**内核驱动级**：关闭无对应硬件或形态不需要的驱动，并同步删除其设备配置，避免"配置已删、加载仍找"的噪声。

此外，内存与分区布局同样纳入小型化：缩小媒体静态内存区、按值守与事件双档位配置视频缓冲池，并按实际内容缩减用户数据分区。

#### 裁剪对象

拟裁剪的非核心组件按族归并为七类，覆盖其"功能定位"与"裁剪依据"：

- **示例应用（2 项）**：相机示例、屏保示例。量产镜像不需要。
- **UI 与 Ability 族（4 项）**：窗口管理、UI 框架、JS UI 引擎、Ability 管理。无屏、无 UI 应用形态，界面与应用生命周期管理能力不需要。
- **软总线与安全族（4 项）**：分布式软总线、设备认证、设备安全等级、分布式任务调度。单体设备无跨设备场景，相应的发现组网、认证与安全评估、跨设备调度能力均不需要。
- **传感器族（2 项）**：传感器框架与传感器驱动。按无 PIR 机型裁剪（人体红外唤醒走 GPIO 直连，不经传感器框架）。
- **无屏外设（3 项）**：显示、振动器、灯驱动。无对应硬件（显示条目删除后其驱动仍被图形组件路径依赖拉起，实际收益有限）。
- **测试与开发工具（4 项）**：XTS 用例、XTS 工具、设备证明、系统能力编解码。量产镜像不需要。
- **应用孵化（1 项）**：应用孵化服务。无 UI 应用形态，组件删除、启动项移除，源码目录留存（供头文件级引用）。

此外，包管理服务与安全密钥服务按按需处理：包管理服务不启动、组件保留；安全密钥服务延迟到启动后段，降低启动期负担。

#### 裁剪边界

并非所有非核心组件都可裁除。经依赖反查，以下能力因公共接口级硬依赖、作为服务框架基座或涉及调试通道而转保留：缓冲队列抽象与图形工具被相机与媒体的公共接口引用；权限鉴权是服务管理框架的基座；国际化与资源管理被 UI 引擎与包管理无条件依赖；用户态音频被媒体组件无条件编译链接；USB 可能承担调试或联网通道，需产品定义后再定。这些项需源码级改造或产品确认才能进一步裁剪，代价较高，暂列保留。

边界是动态的：当某个"阻塞源"组件（如应用孵化服务）被裁除后，其下游组件的阻塞随之消失，可由阻塞转为可裁。

#### 实施与验证

实施遵循三条纪律：

- 顺序纪律：先裁消费者、后裁被消费者，避免组件名依赖找不到；
- 同步纪律：启动配置、内核配置与设备配置成组同步修改；
- 验证纪律：对比必须在全清重建下进行，避免增量构建的陈旧产物干扰判断。

收益评估以实测为准：组件声明值口径不一、普遍偏大，仅作参考；最终以构建产物的文件级体积、镜像大小、启动服务数与运行时内存水位为准。每批裁剪保持可单独回退，并配套核心链路完整性验证与硬件冒烟。

#### 缺口移交

裁剪的代价是部分能力消失，需显式移交产品化补齐：无线配网与连接管理、维护期的下载与上传通道、软件图像编解码、用户数据分区缩减、量产镜像的调试工具清理等。这些缺口在裁剪设计时即行登记，避免产品化阶段遗漏。

### 低功耗方案设计

**核心内容：**
	以"睡得深、时间不丢、醒了时间准"为目标，构建系统级低功耗框架：内核层补齐休眠自动进入、分档准入、设备电源链与无节拍休眠；电源服务与平台/驱动层把休眠接到实际硬件；时间连续性保证录像证据可信；以单帧值守循环与计量体系支撑业务与优化，按"浅 AOV → 标准 AOV → 深睡 AOV"三步推进。

**低功耗方案：**
	构建系统级 AOV 低功耗框架，以支撑全天候持续录像；
	使 OH L1 具备可复用的低功耗基础能力，如状态机、PM 锁治理、唤醒链路、时间连续性等。

#### 设计目标

AOV 要成立，系统层必须同时满足三点：**睡得深（才省电）、时间不丢（才是证据）、醒了时间准（才可信）**。据此确定三项设计目标：

- 能睡：空闲时自动进入低功耗，且休眠准入能区分档位（允许浅睡、禁止深睡）；
- 睡得深：支持无节拍休眠与真实的平台省电动作，逐步逼近深睡；
- 时间连续：休眠、唤醒与掉电后，系统时间与录像时间轴保持连续。

方案沿三层展开：以**功耗状态机**统一运行状态，以**子系统改造**补齐内核、服务、平台与驱动能力，以**计量体系**度量收益。

#### 架构设计

##### 五层架构

- **L5 业务策略层**：状态机主脑与单帧循环业务，决定"何时醒、醒多久、做什么"。
	- aov_policy、单帧循环业务、AI检测、AOV策略服务
- **L4 电源服务层**：把业务的"别睡/可以睡"翻译成内核操作，提供运行锁与挂起/唤醒接口。
	- powermgr_lite
- **L3 内核层**：提供休眠状态机、休眠准入、设备挂起链与时间基座。
	- kernel/liteos_a PM
- **L2 驱动/平台层**：把内核钩子接到具体芯片，并把电源回调分发到各驱动。
	- HDF PM + BSP
- **L1 硬件层**：RTC/GPIO/WiFi/DDR 等物理能力与唤醒源。

其中，tickless、唤醒锁、动态调频、驱动电源管理是操作系统级的横切能力，被上述多层共同依赖；功耗状态机则是集成它们的总框架。

##### 功耗状态机

四级状态对照内核四档，是低功耗的总框架：每级状态对应一组"保持什么、关掉什么、谁能唤醒、唤醒多快"的契约。状态迁移由业务策略驱动，条件包括事件升档、连续无目标降档、电量阈值降档等。

| AOV 状态             | 内核档位        | 进入条件             | 退出/唤醒                                           | 系统行为                                                                             |
| ------------------ | ----------- | ---------------- | ----------------------------------------------- | -------------------------------------------------------------------------------- |
| S0 ACTIVE（全速）      | NORMAL      | AI命中/用户预览/OTA/充电 | 滞回：连续5帧无目标且上传完成                                 | 15~30fps 录像+推流+AI 全开；DVFS 高档                                                     |
| S1 AOV_WATCH（值守）   | LIGHT_SLEEP | ACTIVE滞回满足/开机默认态 | 第一步：任务周期唤醒（usleep+tick）；深睡阶段切 RTC alarm；GPIO/PIR/WiFi WoW → 升 S0 | 单帧循环：周期唤醒→sensor restart→SNAP 采集→编码→AI/MD→攒批落盘→sensor standby→LIGHT 睡；DVFS 低档冲刺 |
| S2 STANDBY（STR 深睡） | DEEP_SLEEP  | 长时无事件或低电量        | RTC/GPIO/WiFi WoW；唤醒后回 S1 或 S0                  | 第三步实现：MPP deinit→驱动 listener suspend→DDR self-refresh→电源域关断；**时间 offset 记录**     |

#### 子系统方案设计

##### 内核层

**空闲自动进入休眠**
	- 现状：空闲任务仅等待中断，未接入电源管理流程，"能睡"的能力形同虚设。
	- 设计：由平台侧覆写空闲任务入口；主核在空闲且无锁时自动触发休眠，若最低档被锁否决则退化为等待，从核保持等待状态。
	- 价值：无需用户态干预即可自动进入低功耗；持锁行为与改造前一致，风险可控。

**分档 PM 锁**
	- 现状：锁为全局一票否决，任一锁存在即所有档都无法进入，无法表达"允许浅睡、禁止深睡"；录像或写卡线程持锁期间系统永不休眠。
	- 设计：将锁计数按档位拆分，每把锁声明其所禁止的档位及更深档位；目标档被否决时自动降级到较浅档，仅在最低档被否决时才放弃本轮休眠。
	- 兼容：按名加锁、超时自动释放等原有用法保持不变，业务侧可平滑迁移（如"录像写卡窗口禁止深睡、允许浅睡"）。

**设备电源链**
	- 现状：仅支持单个设备注册，后注册者会覆盖前者，无顺序与回滚能力。
	- 设计：设备注册改为链表，登记顺序挂起、逆序恢复；部分设备挂起失败时，仅回滚已经挂起的设备，未挂起的不受影响。
	- 价值：为后续逐个挂接存储、时钟、网络等外设预留挂载点。

**无节拍休眠（tickless）**
	- 现状：系统依靠固定间隔的周期节拍实现延时、超时与软定时器，即使完全空闲也会被反复敲醒，难以长睡，是当前最大的功耗缺口。
	- 设计：空闲且可长时间休眠时停掉周期节拍，把唤醒点交给低功耗定时器或实时时钟（指向下一个事件点，无事件则可无限期）；唤醒后以定时器读数补偿节拍计数，保证时间与软定时器不乱。
	- 注意：若存在近周期的定时需求（周期任务、轮询线程），"下一个事件点"本身即为周期，节拍会重新周期性化而抵消收益，应改为事件驱动或拉长周期；是否停节拍还需结合"预期空闲时长是否值得"判断。

##### 电源服务层

**真实挂起**
	- 现状：小型系统的挂起循环为 sleep 假桩，既未真正挂起，又制造周期无效唤醒。
	- 设计：真实挂起交由内核空闲流程自动完成，用户态循环仅保留为策略槽位；挂起准入仍经运行锁生效。
	- 价值：形成"业务空闲 → 系统真睡"的闭环。

**运行锁与挂起/唤醒接口**
	- 复用：运行锁到内核 PM 锁的链路已经贯通，可直接复用。
	- 补齐：挂起/唤醒服务接口需补齐立即挂起语义与权限校验，并接入"加锁即唤醒"标志。
	- 新增：唤醒源管理接口，支撑 RTC 定时唤醒与 GPIO/WiFi 远程唤醒的配置与使能。

##### 平台/驱动层

**平台电源钩子注册**
	- 现状：内核预留了各档休眠的平台钩子，但无人实现。
	- 设计：由平台侧注册系统控制回调，在休眠前后完成计量与时间采样，并实现各档的进入与退出动作。
	- 演进：当前档位以等待中断的浅睡实现，为后续时钟门控、电源域关断等真实省电动作预留填充点；同时覆写空闲任务入口，使平台真正接入电源管理。

**驱动电源回调挂接**
	- 现状：驱动电源管理框架完整（内核桥接、回调接口、状态广播、挂起逆序恢复正序），但实现回调的外设极少。
	- 设计：优先为存储、时钟、实时时钟、网络等外设挂接挂起/恢复回调——存储休眠前同步并降电，网络在主控深睡时维持保活。
	- 工作量：框架已就绪，为逐个挂接。

**动态电压频率调节**
	- 设计：短时唤醒窗口全速冲刺、空闲降频，且与休眠锁互锁（有锁不降频）。
	- 现状：调频寄存器地址已定位，但缺寄存器位域资料，暂列为后续能力。

**媒体处理库的电源策略**
	- 现状：媒体处理库为预编译库，无法在其内部做电源钩子。
	- 设计：深睡时整体去初始化、关断电源域、唤醒后再初始化；模块级退出函数树内已存在但无调用者，需先做稳定性验证。
	- 定位：闭源约束下进入深睡的可行方向。

##### 时间连续性

	- 前提：录像时间轴可信要求"有起点、走得准、掉电不丢、深睡不错"。
	- 设计：以"开机校时 + 网络对时 + 回写 + 深睡补偿"闭环：
		- 开机从实时时钟读取时间设置系统时间，作为时间轴起点；
		- 联网后经网络对时校准，并将校准结果回写实时时钟，以防掉电丢失；
		- 深睡期间计时器随电源域停走，唤醒后以实时时钟差值补偿系统时间，使节拍、软定时器与系统时间跨休眠连续。
	- 说明：对浅睡档位，计时器不停走、补偿自动退化为零，无副作用。

##### 值守期单帧循环

	- 定位：值守期是占空比策略的落地形态，目标是在每个唤醒窗口内完成"取一帧、编码、检测、落盘"后尽快回睡。
	- 循环：唤醒 → 传感器重启 → 单帧采集 → 编码 → 检测 → 攒批落盘 → 传感器待机 → 回睡；检测命中则切入全速录像，连续无目标后滞回值守。
	- 重点：压缩唤醒窗口以降低占空比——循环内不做非必要工作，非必要媒体流与外设驱动在进入值守前关闭；同时落实"上传完成才可休眠"，事件数据落盘后才允许下一轮休眠。
	- 演进：后期可将检测与唤醒决策下沉到低功耗单元，进一步缩短主核参与时间。

##### 快启与启动重排

	- 目标：快启追求最短时间拿到首帧，而非开机时间；首帧越快，占空比唤醒窗口越短、平均功耗越低。
	- 计量先行：先建立全链路分段计量（引导、内核、驱动初始化、首帧），再按结果定位瓶颈。
	- 启动重排：将开机服务分为关键路径、延迟组与裁剪组——关键路径（服务框架与媒体服务）优先拉起，延迟组在首帧达成后或按需启动，其余服务随组件裁剪移除；同时减少非必要打印与加载，缩短关键路径。

##### 计量体系

	- 原则：无计量则无优化。
	- 三类计量：
		- 首帧耗时的分段计量，定位启动瓶颈；
		- 挂起与唤醒耗时的统计，度量休眠开销；
		- 休眠被阻止时持锁者的可观测导出，定位"谁阻止了休眠"。
	- 用途：既是优化依据，也是验收证据。

#### 实施路线

按"先浅后深、先易后难"，分三步推进：

- **浅 AOV（树内可闭环）**：补齐休眠链路与唤醒准入、空闲自动进入、时间连续性、值守期单帧循环，并建立首帧与挂起计量基线。该步不依赖外部资料，是当前可落地的主体。
- **标准 AOV**：挂接驱动电源回调、接入网络保活、实现动态调频、将检测与唤醒下沉，优化至值守功耗目标。部分依赖寄存器资料。
- **深睡 AOV**：在获得芯片低功耗资料后，实现 DDR 自刷新、电源域关断与媒体处理库整体下电，逼近深睡功耗目标。该步受外部资料约束。
