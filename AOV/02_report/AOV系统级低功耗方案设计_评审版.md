## 0. 结论速览

1. **问题本质**：AOV（周期唤醒抓 1 帧、抓完即睡的全时录像）要成立，系统层必须同时满足三件事——**睡得深（才省电）、时间不丢（才是证据）、醒了时间准（才可信）**；而 OpenHarmony L1 恰好在这三处"框架在、实现空"。这是系统层改造的根本动因。

2. **小型化**：按设备真实用途做减法（无屏 → 裁界面框架；单体 → 裁设备互联；只录像 → 裁显示/音频/解码链）。实测**镜像内容 53.9 → 24.6MB（−54.4%）**，开机服务 15 → 7，构建工程量 −37%，录像/检测/升级链路完整性保持。

3. **低功耗**：核心不是降频而是**分档休眠**（CPU 停转 → 外设时钟门控 → 内存自刷新，逐级加深）。系统层补齐五项基础能力：**自动进入休眠、分档休眠锁、设备挂起链表、系统时间补偿、平台级分档钩子**，并配套业务层单帧循环骨架与时间连续性闭环。双平台（双核 + 单核）构建与符号级验证全部通过。

4. **关键硬约束**：dv300 关闭双核不可行——海思媒体库按双核编译，引用其自旋锁符号，单核链接失败；**从核停驻自研是 dv300 深睡的唯一路线**，单核机制验证改由 ev300 承担（已完成对照构建）。

5. **三步走**：浅 AOV（树内闭环，基础能力已全部落地）→ 标准 AOV（驱动监听/DVFS/网络唤醒/移动侦测，对标值守 ≤80mW）→ 深睡 AOV（内存自刷新，依赖海思保密资料，STR ≤40mW）。

## 1. 设计目标与指标

### 1.1 总体目标

在 OpenHarmony L1 小型系统（LiteOS-A）+ 海思 IPC 平台上，构建**系统级 AOV 低功耗框架**（功耗状态机、休眠锁治理、唤醒链路、时间连续性、计量体系），支撑 1fps 值守 + 事件全速录像，并使 OpenHarmony L1 具备可复用的低功耗基础能力。

### 1.2 分步指标

**口径纪律**：全部指标按"整板含传感器、WiFi 保活、25℃、1fps 2MP"口径验收；每项实测附测试条件。业界宣传值与整板实测差异可达 4~8 倍，本节对标值已区分"营销口径"与"实测/官方选型口径"。

| 指标 | 第一步·浅 AOV | 第二步·标准 AOV | 第三步·深睡 AOV | 业界对标 |
|---|---|---|---|---|
| 值守功耗（整板，1fps，含 WiFi 保活） | 建立基线实测（CPU 停转级收益） | **≤80mW 保底 / ≤45mW 竞争** | ≤45mW 稳定达成 | 海思 80mW（营销）/ 国科微单板 42mW / 君正 T33 26mW |
| 深睡功耗（整板，内存自刷新） | — | — | **≤40mW 保底 / ≤10mW 竞争** | RV1126B 核心板 7mW / 裸片 1mW 级 |
| 唤醒延迟（唤醒源→首帧出图） | ≤1s | **≤500ms** | ≤250ms | 君正 TTFF<90ms / RV1106 250ms |
| 事件切换（检测命中→全速录像） | ≤2s | ≤1.5s | **≤1s** | RV1106 1s |
| 冷启动首帧（上电→首帧） | 分段测量建基线 | ≤1.5s | **≤1s** | 全志 V853 700ms |
| 时间连续性 | 值守 24h 时间轴误差 ≤1s | + 联网周期校时 | 深睡 7 天唤醒误差 ≤1s | — |
| 续航折算（9000mAh） | — | ≥10 天 | **≥13 天** | 觅睿 V7 13~15 天 |
| 存储占用 | ≤1GB/天 | ≤600MB/天 | 同左 | 觅睿 600MB |

> 若第三步保密资料不可得，方案上限锁定为"浅 AOV + WiFi 保活"组合，指标按保底列执行。

## 2. 总体架构

### 2.1 五层架构

```
┌──────────────────────────────────────────────────────────────┐
│ L5 业务策略层   值守策略服务（状态机主脑）+ 单帧循环 + 移动侦测    │
├──────────────────────────────────────────────────────────────┤
│ L4 电源服务层   电源管理服务：唤醒锁(复用) + 挂起准入(复用)        │
│                 + 唤醒源管理(新增) + 电池对接(替换模拟值)          │
├──────────────────────────────────────────────────────────────┤
│ L3 内核层       LiteOS-A 电源管理：分档休眠锁 + 设备挂起链表        │
│                 + 系统时间补偿 + 空闲自动休眠                       │
├──────────────────────────────────────────────────────────────┤
│ L2 驱动/平台层  驱动 PM 框架(复用) + 平台分档钩子(新增)             │
│                 驱动级挂起监听(逐个挂接) + 媒体库电源(新增)         │
│                 动态调频(新增) + WiFi 网络唤醒桥接(新增)            │
├──────────────────────────────────────────────────────────────┤
│ L1 硬件层       hi3516 dv300/ev300                                │
│                 RTC / GPIO / WiFi 芯片(网络唤醒) / SD 卡           │
│                 电源域与内存自刷新(第三步，依赖海思保密资料)          │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 功耗状态机（核心设计）

四级状态，与 LiteOS-A 原生四档休眠（普通/浅睡/深睡/关机）一一映射，由业务策略服务集中管理：

| 状态 | 内核档位 | 进入条件 | 退出/唤醒 | 系统行为 |
|---|---|---|---|---|
| S0 全速 | 普通（持锁不入睡） | 检测命中 / 预览 / 升级 / 充电 | 连续若干帧无目标且录像落盘、上传完成 | 15~30fps 录像 + 推流 + 检测全开 |
| S1 值守 | 浅睡 | 开机默认 / 全速退出满足 | 周期唤醒（1s 节拍）；外设/网络唤醒 → 升 S0 | 单帧循环：唤醒 → 出帧 → 编码 → 检测 → 攒批落盘 → 睡眠 |
| S2 深睡 | 深睡 | 长时间无事件或低电量 | RTC / GPIO / 网络唤醒 | 媒体库退初始化 → 驱动挂起 → 内存自刷新 → 电源域关断 |
| S3 软关机 | 关机 | 极低电量 / 指令 | 网络云指令 / 按键长按 | 主控下电，仅 WiFi 保活 |

**状态切换强约束**（写入策略服务）：
- **上传完成才可休眠**：从全速退回前，事件录像必须落盘、告警必须上传完成；
- **低电量降档**：电量阈值触发逐级降档，太阳能输入可升档；
- **看门狗防睡死**：值守循环与深睡均设超时兜底；
- **竞态保护**：休眠入口原子检查"锁计数 + 未决唤醒事件"，避免漏唤醒。

## 3. 子系统方案设计

### 3.1 内核层增强（LiteOS-A 电源管理）

| 改动 | 设计要点 |
|---|---|
| 分档休眠锁 | 原为单一计数（一锁全禁），改为**按档计数**：新增分档锁接口，可表达"禁止深睡、允许浅睡"，并支持自动降级（深睡被否决时降为浅睡而非放弃）。旧接口语义不变，兼容存量调用方 |
| 系统时间补偿 | 新增全局时间补偿量：所有系统时间读取统一叠加该量；浅睡时无影响，深睡前记录时刻、唤醒后按 RTC 差值补回丢失时间——保证深睡后定时器/超时/录像时间戳不中断 |
| 设备挂起链表 | 原设备挂起为单指针（后注册覆盖先注册），改为链表 + 节点池；按注册顺序挂起、逆序恢复；单个设备失败可回滚 |
| 空闲自动休眠 | 覆写内核空闲任务：无锁时自动进入休眠流程，而非仅 CPU 停转空转；睡眠决策失败的竞态由入口二次检查兜底 |
| 缺陷修复 | 锁等待语义修正（区分超时与成功）、挂起竞态校验参数启用、挂起触发权限修正 |

### 3.2 电源服务层扩展（电源管理服务）

| 改动 | 设计要点 |
|---|---|
| 真实挂起 | 移除"用延时模拟挂起"的占位实现，真实挂起交由内核空闲钩子接管，服务层保留准入判断（唤醒锁 → 内核锁计数） |
| 唤醒源管理 | 新增唤醒源注册/启停接口：RTC 定时、GPIO 边沿、WiFi 网络唤醒、串口；服务侧统一维护唤醒源表，挂起前下发给驱动层 |
| 电池对接 | 替换写死的电量模拟值，对接真实电量计/充电采集；PoC 阶段可用分压采样近似 |
| 挂起语义补全 | 立即挂起参数生效、权限校验、加锁即触发唤醒链路 |

### 3.3 平台/驱动层

| 改动 | 设计要点 |
|---|---|
| 平台分档钩子 | 新增平台电源管理实现，向内核注册四档回调：普通/浅睡档实现 CPU 停转（集群时钟门控待寄存器资料填充），深睡档先搭建"记录时刻 + 时间补偿"框架，真实电源域关断待保密资料 |
| 驱动挂起监听 | 按保留外设逐个挂接驱动电源回调：SD 卡（写前同步 + 断电）、RTC（保持为唤醒源）、GPIO（唤醒引脚配置）、串口（接收唤醒）、WiFi |
| WiFi 网络唤醒桥接 | 复用芯片已有的低功耗 + 网络唤醒能力：进入浅睡/深睡前配置唤醒规则，主控睡眠后 WiFi 保活，云指令经网络唤醒拉起主控；保活间隔参数化（时延 vs 功耗权衡） |
| 媒体库电源策略 | 对称接管媒体库的整体退出/初始化接口（树内已存在但无人调用）：深睡前按序退初始化、唤醒后重初始化，闭源边界下唯一深睡路径；同步重配媒体内存区（384MB → 128~192MB）与视频缓冲双档位（值守小池 / 事件大池） |
| 动态调频 | 直操作 CPU 调频寄存器实现两档（全速 / 值守冲刺），切换点绑定状态机迁移，与休眠锁联动 |

### 3.4 时间连续性方案

```
冷启动   开机读取 RTC → 写入系统时间（新增开机校时）
联网后   启动 SNTP 客户端（真实编入，替换空占位）→ 周期校时 + 校时结果写回 RTC
值守期   每帧录像时间戳取自系统时间（以 RTC 为基准，时间轴连续）
深睡     睡前记录时刻 → 醒后按 RTC 差值补偿系统时间（见 3.1）
```

新增轻量时间同步服务：开机 RTC 校时 + SNTP 周期校时 + 校时写回 RTC，三保险（RTC 起点 / 联网校准 / 回写防掉电）。

### 3.5 值守期单帧循环（业务接口约定）

业务策略服务驱动的值守主循环（周期 1s，可配 0.5~4s 缩时）：

```
1. 周期唤醒（浅睡阶段由心跳唤醒；深睡阶段由 RTC 定时唤醒）
2. 系统时间校验（深睡补偿）
3. 传感器重启（出帧消隐 ≥33ms 约束）
4. 单帧采集（MPP 单帧触发模式）
5. 编码（H.264/H.265，I 帧间隔策略，缩时录像标记）
6. 移动侦测（帧差法 / 硬件检测 / 神经网络三选一，768×448 子流）
   命中 → 升全速（事件录像 + 告警上传）；未命中 → 继续
7. 攒批落盘（缓冲满 1MB 或事件/休眠前刷新；FATFS）
8. 传感器待机
9. 外设降电（SD 断电、WiFi 保活）
10. 设置下一唤醒时刻 → 进入浅睡
唤醒窗口（步骤 3~9）预算 ≤100ms（业界经验：每省 5ms 续航近翻倍）
```

### 3.6 快启与启动重排

- 开机服务三分组：关键路径（出首帧必需）、延迟组（首帧后触发启动）、裁剪组（按用途移除）；
- 延迟组以"首帧达成"事件触发，而非固定延时；
- 媒体模块初始化按值守最小集优先，事件专有模块延迟初始化；
- 全链路分段测量，无量不打点、无打点不验收。

### 3.7 计量体系（"无计量则无优化"）

| 计量项 | 实现 | 输出 |
|---|---|---|
| 冷启动首帧分段 | 引导段（预编译，用 GPIO 翻转 + 示波器替代）/ 内核各阶段 / 媒体模块逐一 / 业务首帧 | 分段瀑布图 + 预算告警 |
| 挂起/唤醒耗时 | 进出时间差累加，周期性输出次数/均值/峰值/当前锁数 | 唤醒窗口预算达成率 |
| 锁审计 | 扩展锁信息展示：持锁者 + 档位 + 计数 | 定位"谁阻止休眠" |
| 功耗实测 | 整板功率计（≥10Hz）+ 各功耗域电流探针 + 软件状态驻留时长统计 | 指标验收 + 功耗模型校准 |

## 5. 关键设计决策与理由

| 决策 | 选择与理由 |
|---|---|
| 状态机载体 | 策略服务（新增）承载状态机主脑 + 媒体侧承载数据面，控制面与数据面分离；电源服务保持通用定位不绑业务 |
| 一阶段验证平台 | 单核平台先行（规避双核从核问题），机制验证后平移双核；两板媒体库不同构，业务层按平台无关接口设计 |
| 深睡路径 | 双线并行：保密资料可得走深睡（上限路线），不可得走"浅 AOV + WiFi 保活"（保底路线）；外部确认即刻启动 |
| 休眠锁兼容 | 新增分档接口而非改旧接口语义（存量调用零影响） |
| 时间补偿位置 | 必须在内核注入（系统时间读取是定时器/超时/日志的公共地基，应用层无法兜底）；应用层 RTC 校时解决绝对时间，两者正交 |
| 媒体库电源策略 | 通道级启停优先（代价小、闭源风险低），模块级退初始化仅深睡前执行 |
| 唤醒节拍 | 可配 + 自适应缩时：无事件超时后拉长间隔省电，事件后恢复 1s 防漏录 |
