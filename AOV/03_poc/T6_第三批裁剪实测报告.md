## 2. 重要实证发现：dv300 关 SMP 不可行（修订阶段 2 P1-5 / PoC 计划）

- **现象**：关 `LOSCFG_KERNEL_SMP{,_LOCKDEP,_TASK_SYNC}` 后内核链接失败，海量未定义符号：`LOS_SpinLock / LOS_SpinUnlock / LOS_SpinInit / LOS_SpinLockSave...`（1728+ 处引用）
- **根因**：SMP 开启时 spinlock 为真实函数（los_spinlock.c）；UP 构建下退化为头文件 static inline 空操作。而**海思 MPP 预编译静态库**（`base_mod_init`/osal）、**dwc_usb3** 等均以 SMP=y 环境编译，按 out-of-line 符号引用 spinlock → UP 内核无此符号 → 链接失败
- **结论与修订**：
  1. **"dv300 关 SMP 做单核原型"路线被实证否决**（除非海思提供 UP 编译的 MPP 库，归入 NDA 沟通清单）；
  2. dv300 深睡路径必须**自研从核 park 机制**（阶段 4 P1-5 备选方案升为唯一方案：从核 `smp.c:99-101` 独立 WFI 路径需增加下线钩子）；
  3. 单核机制验证平台改用 **ev300/aries**（原生单核；其 MPP 为 .so 动态库形态，SMP 依赖性待其构建时验证）；
  4. 附带收益保留：SMP_LOCKDEP 为调试特性，量产可评估单独关闭（需同验 MPP 链接，本批未动）。

## 6. 结论

1. 第三批（内核侧）**构建验证通过**：OHOS_Image -108KB、内核符号零残留、启动服务 15→7；**SMP 关闭被实证否决**并转化为从核 park 设计输入（本批最大工程价值）；
2. 三批累计：内容体积 **-54.4%**（53.9→24.6MB，10^6 口径）、构建目标 -37%、启动服务 -53%，全部经 clean 重建 + 符号/文件级实证；
3. 全部改动收敛于 vendor 仓（10 文件）+ 5 个组件仓元数据补丁，patch 齐备可回退；
4. T6 本地可验证部分**全部完成**；后续 T1~T5/T7 与硬件冒烟清单待板卡环境。
