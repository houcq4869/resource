## 2. 核心设计要点（pm_hi35xx.c）

1. **OsIdleTask 覆写（K4 方案 A）**：
   - 链接机制实证：vendor 平台库在 `hdf_lite.mk:35~185` 的 **--whole-archive 区间**内链接 → 新 object 强制加载 → strong `OsIdleTask` 覆写内核 WEAK 版（符号尺寸 8B→136B 实证，见 §3）；
   - **非阻塞设计**：idle 循环用 `LOS_PmLockCountGet()==0` 判断（而非 LOS_PmReadLock 事件阻塞——idle 任务 pend 会破坏调度不变式）；竞态由 `LOS_PmSuspend` 内部关中断二次检查（lock/isWake）兜底；
   - **SMP 从核 park**：`ArchCurrCpuid()!=0` 分支保持裸 WFI（dv300 双核；从核深睡 park 属第三步课题，本补丁不改变从核行为）；
   - 锁持有时退化为裸 WFI = 与基线行为一致（零回归风险）。
2. **SYSCTRL 惰性注册**：在 CPU0 idle 首次运行时注册（idle 任务必然晚于 `OsPmInit`（KMOD_EXTENDED level）→ 时序安全，规避同级 LOS_MODULE_INIT 顺序不确定问题）；注册采用按字段合并语义，仅覆盖 `early/late/normalSuspend/lightSuspend`，其余档位保留内核默认（DEEP=第三步填充位）。
3. **静默 normalSuspend**：替换默认 handler 的 `PRINTK+WFI`（否则 idle 每次挂起串口刷屏）。
4. **LIGHT 档第一阶段 = 完整 sysctrl 时序 + WFI**：功耗与基线 WFI 同级（收益在链路打通+可计量）；时钟门控序列留待 CRG 寄存器资料（B1 第二/三步填充点已在注释标注）。
5. **挂起计量（T1）**：early 记 tick / late 算耗时，累计 count/total/max，每 64 次挂起输出一条 `[AOV-PM] suspends=N last=Xms avg=Xms max=Xms locks=N`（防日志刷屏；PM_STAT_DUMP_PERIOD 可调）。
6. **档位切换/锁接口零新增**：复用 `/proc/power/power_mode`（normal/light/deep 切换）与 `/proc/power/power_lock`（powermgr_lite RunningLock 已对接）——测试与业务均走既有通道。

## 5. 已知限制与下一步

1. **T4 时间连续性未含在本轮**：开机 RTC 校时 + sntp 编入（录像时间轴必需）与内核 offset（DEEP 前置，LIGHT 阶段不需要）——下一轮补丁；
2. **LIGHT 档无真实功耗收益**（=WFI）：时钟门控需 hi3516dv300 CRG 寄存器资料（`PERI_CRG30_BASE` 已定位，外设门控位图需 SDK 文档/NDA）——列入外部资料需求清单；
3. **HDF device 广播在每次挂起执行**（devmgr_pm_reg 已注册 DEVICE 节点）：当前零 listener 成本可忽略；驱动 PM listener 逐个挂接后（第二步 B2）需复测挂起延迟，必要时 K3 链表化+顺序控制提前；
4. **从核 park**：dv300 从核仍裸 WFI（SMP 关闭被 MPP 预编译库否决——第三批实证），深睡前必须解决从核下线/保持域划分（第三步课题）；
5. `power_count` 0664 后用户态可直接写触发挂起（测试便利）；产品化建议改走 syscall/服务接口并加权限校验（阶段 4 S4）。
