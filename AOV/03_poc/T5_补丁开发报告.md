## 2. 设计要点（与阶段 4 §3.5 十步循环的对应）

| 循环步骤（设计） | 骨架实现 | 状态 |
|---|---|---|
| RTC/定时唤醒 | 第一阶段用 `usleep(interval)` 任务延时——**期间内核 idle PM 钩子（T2）自动挂起 CPU**，tick 中断按时唤醒；深睡阶段（第三步）切 RTC alarm（tick 停走时） | ✅ 机制对齐 |
| sensor restart | `stSnsImx335Obj.pfnRestart(pipe)` + 100ms 稳定延时 [TUNE]——**头文件实证发现 `ISP_SNS_OBJ_S` 直接导出 `pfnStandby/pfnRestart`**（hi_sns_ctrl.h:64-65），kol SINGLE 模式同款机制用户态可直调 | ✅ |
| 单帧采集 | `HI_MPI_SNAP_SetPipeAttr`（NORMAL 型、非 ZSL、深度 1、间隔 1）+ `EnablePipe` + 循环内 `TriggerPipe` | ✅ |
| 编码 | VENC H.264 CBR 512kbps（值守低码率 [TUNE]）、VI→VENC SYS_Bind、`StartRecvFrame(recvPicNum=1)` 与触发配对 | ✅ |
| AI/MD 检测 | `AovMdCheck()` 桩（返回无事件→纯缩时模式，君正 0.5~4fps 缩时为业界有效形态）；第二步接 libmd/IVE/NNIE（768×448 子流） | 🟡 桩 |
| 攒批落盘 | 1MB batch 缓冲，满批/事件/退出时 `write+fsync`；时间戳分段文件名（`aov_YYYYmmdd_HHMMSS_idx.h264`，联动 T4 校时）；段内 3600 帧轮转 | ✅ |
| sensor standby | 循环尾 `pfnStandby(pipe)`（休眠前外设降电） | ✅ |
| 休眠 | usleep 窗口内由 T2 idle 钩子接管（锁计数=0 即挂起；powermgr WakeupHolder 准入链路生效） | ✅ 机制联动 |
| 事件突发 | `AovActiveBurst()`：`StartRecvFrame(-1)` 连续接收 + RequestIDR + 15s/滞回退出 + 立即 flush（"上传完成才可休眠"前置）+ 退回 1 帧接收模式 | ✅（MD 桩期不可触发） |
| 计量 | 周期耗时 max 统计 + 每 64 周期打印（cycles/frames/bytes/flush/active/costMax）| ✅ |

**ISP 策略**：第一阶段 ISP Run 线程常驻（保出图优先）；[TUNE] 第二步切 `HI_MPI_ISP_RunOnce` + 曝光参数缓存（kol Fast AE 3 帧收敛模式，阶段 1 报告 §2.2）——API 已确认在头（mpi_isp.h `RunOnce`）。

## 3. 构建排障记录（可复用知识）

### 3.1 CV500 结构体字段勘误（vs 通用印象）
| 项 | 实际定义（sdk_liteos/include 实证） |
|---|---|
| VI dev 接口模式枚举 | `VI_MODE_MIPI`（非 VI_INTF_MIPI） |
| VI_PIPE_ATTR_S | `enPipeBypassMode/bYuvSkip/bIspBypass/u32MaxW/u32MaxH/enPixFmt/enBitWidth/bNrEn/bSharpenEn/stFrameRate`（无 stSize/enPipeType） |
| ISP_SNS_ATTR_INFO_S | 仅 `eSensorId`（hi_comm_sns.h:34，无 s32SnsId/s8SnsDev/s32BusId——总线经 `pfnSetBusInfo(ISP_SNS_COMMBUS_U)` 单独设置） |
| ISP_SNS_OBJ_S 位置 | `hi_sns_ctrl.h`（含 pfnStandby/pfnRestart/pfnSetInit 等 11 个钩子） |
| VENC RC 字段 | `stH264Cbr`（非 stAttrH264Cbr）：`u32Gop/u32StatTime/u32SrcFrameRate/fr32DstFrameRate(HI_FR32)/u32BitRate` |
| RequestIDR | 双参 `(VENC_CHN, HI_BOOL bInstant)` |

### 3.2 MPP 用户态可执行链接闭包（--no-allow-shlib-undefined 要求全解析）
`-lmpi -lisp -lsns_imx335 -l_hiae -l_hiawb -l_hiacs -l_hicalcflicker -ldnvqe -lupvqe -lVoiceEngine -lsecurec -l_hidehaze -l_hidrc -l_hildci -l_hiir_auto`
（后四者经 `nm -D --defined-only` 对 `isp_alg_register_dehaze/drc/ldci、isp_ir_auto_run_once` 逐符号定位；库均在 sdk_liteos/mpp/lib 且已随 copy_mpp_libs 入 rootfs/usr/lib）。**此清单即 L1 小系统直调 MPP 的用户态程序标准链接模板**。

### 3.3 验证证据
- `rootfs/bin/aov_poc` 14.4KB 入镜像；
- `readelf -d`：DT_NEEDED 全部为 SONAME（无构建机绝对路径），运行时 /usr/lib 可解析；
- 与既有镜像零冲突（media_server 并存，无 camera 客户端打开即无管线争用）。

## 5. 已知限制与第二步

1. MD 为桩（纯缩时模式）→ 第二步接 libmd：**已 nm 实证 `libmd.so` 导出 `HI_IVS_MD_*` 族**（Init/Exit/CreateChn/DestroyChn/SetChnAttr/GetChnAttr/Process/GetBg 共 8 符号；hi_md.h 仅含 MD_ATTR_S 等类型，函数声明需按 IVS MD 头或自行 extern），或 IVE 帧差；
2. 存储为裸 H.264 段（PoC 口径）→ 产品化接 media_lite recorder MP4/TS 封装（recorder 分段 API 已在阶段 2 确认可用）或轻封装；
3. VB 池沿用内核默认 → 第二步值守/事件双档位重配（阶段 3 §3 MMZ 方案）；
4. ACTIVE 突发计时为粗粒度（帧数折算）→ 联调期换 gettimeofday 差值；
5. 未做 OSD 时间戳叠加（RGN 模块）→ 录像可回溯性需要，第二步补 `HI_MPI_RGN` 附着 VENC。
