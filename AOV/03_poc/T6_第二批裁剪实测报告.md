## 2. 构建排障记录（重要工程知识，4 项）

### 2.1 feature 校验失败：safwk bundle.json 尾随空格 bug

- 现象：`The product use a feature that is not supported by this part, part_name='safwk_lite', feature='safwk_lite_feature_enable_abilityms'`（LOAD 阶段，错误码 2006）
- 根因：`safwk_lite/bundle.json:25-27` 三个 feature 声明**均带尾随空格**，而 `build/hb/services/loader.py:261-267` 做精确字符串匹配 → 任何产品都无法通过 config.json 配置这三个开关（上游 bug，可提修复）
- 修复：bundle.json 去尾随空格（patch：T6_batch2_safwk_bundle.patch）

### 2.2 `ohos_build_type` 恒为 debug（新 hb 硬编码）

- `build/hb/resolver/build_args_resolver.py:721`：`target_generator.regist_arg('ohos_build_type', 'debug')`，注释原文 **"For historical reasons, this value must be debug"**——`-b release` 只影响 is_debug/runtime_mode（编译优化仍为 release 级），但：
  - **内核配置恒取 `kernel_configs/debug.config`**（`liteos_config_file="${ohos_build_type}${tee}.config"`）→ **阶段 2/PoC 计划中"改 release.config 关 SMP"的表述修正为改 debug.config（当前生效文件）**；已确认 debug.config 含 `LOSCFG_KERNEL_SMP=y`（+LOCKDEP/TASK_SYNC）
  - 所有 `if (ohos_build_type=="debug")` 条件目标（各组件 test）**恒被构建** → 引出 2.3/2.4 两条隐性链

### 2.3 隐性链 A：camera test → ui_lite → wms_server

- 现象：arkui/window 段已删，但 libui/libfreetype/wms_server 仍在镜像
- 溯源（`gn refs`）：`media_lite bundle.json sub_component → camera_lite/test:lite_camera_unittest → ui_lite:ui_lite → ui_lite:ui → window_manager_lite:window_manager_lite`
- 修复：media_lite bundle.json 删 3 个 test sub_component（lite_camera_test/lite_medialite_test/lite_audio_test）

### 2.4 隐性链 B：hilog test → ace_kit_hilog → jerry

- 现象：ace 段已删+kit 库已摘，但 libace_kit_hilog/jerry-core/ace_common/native_engine 仍在
- 溯源：`hilog_lite bundle.json sub_component → test:hilog_lite_test →（test/BUILD.gn:47）frameworks/js/builtin:ace_kit_hilog → ace jsfwk → jerry`
- 修复：hilog_lite bundle.json 删 test sub_component
- **方法论沉淀**：小系统"量产镜像"必须清理各 bundle.json sub_component 中的 **test 目标**（ohos_build_type 恒 debug 使其必建），且 test 目标常是 UI/JS 框架残留的隐性拉入方——裁剪验证必须以 `gn refs` + 镜像 readelf 实证，不能只看 config.json

## 4. 意外发现与归因

1. **libcurl/libnghttp2 消失**：残留二进制 readelf 零硬链接、sys_installer_lite 零 curl 引用 → **无害**；归因为被裁集（软总线/test 族）传递依赖。**行动项**：维护期"事件上传/远程下载"通道需显式引入 third_party/curl 组件或自建轻量 HTTP 客户端（阶段 3 §2.3 本就列为自建任务，此处从"可选"升级为"必做"，列入第三批/阶段 4 维护期设计）。
2. **libjpeg/libpng 消失**：UI 图像解码配套；AOV 抓拍走 MPP 硬件 JPEGE（内核态），不受影响；若业务需软解码 JPEG（缩略图等）再显式引入。
3. **bundle_daemon bin 保留**：permission_lite ipc_auth → appexecfwk_services_lite 链（核查表预判成立）；不启动即无功耗影响，bin 51KB 留待 permission 解耦二期。
4. **foundation bin 3976→3888B**：abilityms/dtbschedmgr 注册构造器移除的间接证据。

## 6. 结论

1. 第二批裁剪**构建验证通过**（零错误，5183 targets），累计收益 **-29.3MB(-54.3%) / 构建目标 -36.2% / 启动服务 15→8**，全部经 clean 重建 + 文件级 diff + readelf 实证；
2. 发现并修复 2 个上游问题（safwk bundle.json 尾随空格 bug、test 目标隐性拉入链×2），沉淀 1 个关键构建认知（**ohos_build_type 恒 debug → 内核配置生效文件为 debug.config**，已同步修正 PoC 计划相关表述）；
3. 录像/AI/存储/电源/OTA 保留链路完整性验证通过；libcurl 消失定性无害并转化为维护期设计行动项；
4. 工作树处于"第一批+第二批已应用"状态（6 个 patch 归档，可按 commits 记录逐仓恢复）；第三批（内核侧）与硬件冒烟待板卡。
