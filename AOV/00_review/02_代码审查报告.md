**🔴 S1 自旋锁重入死锁（已复核属实）**：

**🔴 S2 deep 钩子非法上下文（已复核属实）**：

**🟡 M1**：`g_osPmTimeOffsetCycle` 64 位 +=（los_pm.c:473-475）在 32 位 ARM 上非单条指令，读者 `OsGetCurrSchedTimeCycle` 无锁读 → 撕裂读（概率低，后果为时间轴跳变）。建议写入侧在 `LOS_PmTimeOffsetAdd` 内关中断或使用 32 位高低位 seqlock 技巧。

## 附录 A：严重项修复补丁（建议稿，未应用到源码）

### A.1 S1 修复：late 回调移出 g_pmSpin 临界区

思路：EXIT 路径先解锁/恢复调度，再执行设备 resume 与 `late` 回调——回调可 PRINTK、可重入 PM API，语义更健康（对齐 Linux "resume 在 IRQ 使能后"）。

```diff
--- a/kernel/extended/power/los_pm.c
+++ b/kernel/extended/power/los_pm.c
@@ EXIT:
     pm->sysMode = LOS_SYS_NORMAL_SLEEP;
-    OsPmResumePrepare(pm, (UINT32)mode, prepare, devSuspended);
-
     LOS_SpinUnlockRestore(&g_pmSpin, intSave);
     LOS_TaskUnlock();
+    /* S1 fix: 设备 resume 与 sysctrl->late 移出 g_pmSpin 临界区。
+     * 回调可能 PRINTK、重入 LOS_PmLockCountGet 或睡眠（如 RTC SPI 读取），
+     * 在关中断+持锁上下文执行会死锁。 */
+    OsPmResumePrepare(pm, (UINT32)mode, prepare, devSuspended);
     return ret;
 }
```
