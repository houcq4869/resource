## 1. K1：分档 PM 锁（修复阶段 2 P1-1"全局一票否决"）

### 1.1 语义设计

- 锁档位 `mode ∈ {NORMAL, LIGHT, DEEP, SHUTDOWN}`，**档位 M 的锁否决 M 及更深档位**，浅档不受影响（对齐 Linux PM QoS / Zephyr 状态锁语义）；
- 挂起时**自动降级**：目标档被否决 → 降到最浅持锁档的上一档（而非原实现的整体放弃）；NORMAL 被否决才放弃本轮；
- **向后兼容**：`LOS_PmLockRequest/LOS_PmTimeLockRequest` 原 API 语义不变（= NORMAL 档锁，否决所有），powermgr_lite RunningLock 链路（/proc/power/power_lock）零改动兼容。

### 1.2 新 API（los_pm.h 已声明，含 doxygen）

```c
UINT32 LOS_PmLockRequestEx(const CHAR *name, LOS_SysSleepEnum mode);
UINT32 LOS_PmTimeLockRequestEx(const CHAR *name, UINT64 millisecond, LOS_SysSleepEnum mode);
```

**AOV 业务用法示例**（阶段 4 状态机的锁表达）：
| 场景 | 锁调用 | 效果 |
|---|---|---|
| 值守期录像/写卡窗口 | `TimeLockRequestEx("aov_cycle", 500, LOS_SYS_DEEP_SLEEP)` | 禁 DEEP/SHUTDOWN，允许 LIGHT（单帧循环间隙照常浅睡）——**修复原"录像线程持锁→永不休眠"死结** |
| 事件期全速录像 | `LockRequestEx("aov_active", LOS_SYS_NORMAL_SLEEP)` | 禁所有档（原语义） |
| 网络上传中 | `TimeLockRequestEx("upload", 30000, LOS_SYS_DEEP_SLEEP)` | 上传期禁深睡，超时自动释放（防泄漏） |

### 1.3 实现要点

- `LosPmCB.lock`（UINT16 标量）→ `lock[LOS_SYS_SHUTDOWN+1]` 分档计数数组；锁节点 `OsPmLockCB` 增 `mode` 字段（同名重复请求沿用首次档位，Release 按节点档位递减）；
- `OsPmSuspendCheck`：自浅向深扫首个持锁档 → NORMAL 否决返 NOK / 更深否决则 `sysMode = i-1` 降级；
- 临界区二次检查同步分档化（Check 后新增 ≤sysMode 档锁 → 放弃）；
- `LOS_PmLockCountGet` = 全档总和（兼容既有调用方）；`LOS_PmLockInfoShow` 增档位列（持锁审计可读性）；
- idle 钩子（pm_hi35xx.c）简化为 `LOS_PmSuspend(0) != LOS_OK → WFI`：分档否决/降级全部收敛到内核路径，钩子无需感知锁状态。

## 2. K3：设备注册链表化（修复阶段 2 P1-2"单指针覆盖"）

- `LosPmCB.device`（单指针，后注册静默顶掉前者）→ `deviceList` 双向链表 + **池化节点**（`g_pmDevicePool[8]`，静态分配零运行期内存、无碎片）；
- 注册：去重（同指针幂等）+ 空闲槽扫描（支持注销复用）+ 池满返 ENOMEM（原实现池满不可能，因单指针）；
- **挂起/恢复时序**：注册序 suspend、**逆序 resume**（"越底层越晚睡越早醒"，对齐 Linux dpm_list 语义）；
- **部分失败回滚**：`devSuspended` 计数——第 N 个设备 suspend 失败时，仅逆序 resume 已成功的 N-1 个（原单设备实现无此问题，多设备必须）；early 失败则设备全不动、late 不调（prepare 标志语义保持）；
- 注销（`OsPmDeviceUnregister`，既有 API）改链表摘除 + 槽位释放；
- 现状：当前唯一注册者仍是 HDF devmgr_pm_reg（LOS_PM_TYPE_DEVICE）；**第二步驱动 listener 逐个挂接（mmc/rtc/gpio/wlan）时多设备能力就绪**。

## 3. K5：wakeCount 竞态启用（修复阶段 2 P2 项）

- `LOS_PmSuspend(wakeCount)` 原实现丢弃参数 → 现语义：**wakeCount = 调用方读取的锁计数快照，0 = 不校验**；临界区内快照 ≠ 当前总数 → 放弃本轮休眠（Linux wakeup_count 竞态语义的锁计数版）；
- 用途：用户态/服务层"读计数→决策→休眠"窗口内发生的锁变化不再丢失（防"决策后、入睡前"竞态窗口）；
- 兼容性：既有调用方（mini auto_suspend 传 ReadLock 返回值、idle 钩子传 0）行为不变——非 0 且不等才放弃，属保守方向。

## 6. 遗留与边界

1. `LOS_PmReadLock` 等待语义仍为"全部锁释放"（未按档等待）——按需再扩展（当前 idle 钩子不依赖它）；
2. 锁档位不支持运行中变更（同名重请求沿用首档）——文档已注明"先 Release 再 Request"；
3. `OsPmTickTimerStop/Start` 仍为空桩（LIGHT 档 CNTPCT 不停走无需；DEEP 真实停走时与 T4b offset 联动填充——第三步）；
4. SHUTDOWN 档仍被内核默认拒绝（shutdownSuspend=NULL，ModeSet 校验）——第三步 SOFT_OFF 实现时注册。
