## 1. 构建打通结论

### 1.1 构建命令与结果

### 1.2 构建流程关键认知（新 hb 流程，排障记录）

1. **SDK 预构建前置**：本树 manifest 为 6.1 世代新 hb（build/hb/main.py），`--prebuilt-sdk=true` 默认注入（build.sh:209）；`prebuilts/ohos-sdk/linux/23` 不存在时**先整体构建 ohos-sdk**（out/sdk，21431 targets，本机约 10 分钟），完成后归档至 `prebuilts/ohos-sdk/linux/23`，**后续构建自动跳过**（`prebuilt_sdk.py:39-56` should_build_sdk 检查该路径）。可用 `--no-prebuilt-sdk=true` 跳过（源码内官方提示）。
2. 产品构建：`hb build` → gn+ninja → `out/hispark_taurus/ipcamera_hispark_taurus/`，目标 `images`（8124 targets），编译器为 prebuilts clang（small 系统新流程），MPP 以预编译 .a 静态链入 OHOS_Image。
3. **坑位记录**：
   - 长构建必须 `setsid nohup ... < /dev/null &` 脱离会话，否则随 shell 超时被杀（首次构建 2571/24001 处被杀，ninja 增量可续）；
   - build.sh 成功信息 `=====build  successful=====` 产品名为空（脚本变量作用域问题，仅显示缺陷）；
   - out/ 中 `hispark_taurus/ipcamera_hispark_taurus_linux/build.log` 的 Broken pipe 为**此前 Linux 变体构建的历史失败记录**，与本次 liteos_a 构建无关；
   - ohpm/node 初始化告警（Node 14 < 推荐 18）不阻塞构建。

## 3. 裁剪收益预估修正（T0 实测口径 → 替代阶段 3 声明值预估）

| 批次 | ROM 收益（实测口径估算） | 构成 |
|---|---|---|
| 第一批（9 项+字体） | **~19.5 MB** | 字体 17MB + deviceauth 族 ~1.05MB + dslm/devattest 族 ~0.3MB + huks 延迟（bin 保留，收益为启动时间非 ROM）+ light 驱动（内核侧数十 KB） |
| 第二批（软总线+UI+按需） | **~6.5 MB+** | softbus 族 3.67MB + UI 族 2.65MB + wms/appspawn bin 52KB + 内核侧 audio/HDF_SENSOR 关闭（OHOS_Image 内，待对比实测）+ libcrypto 溯源后可能追加 |
| 二期候选 | ~2.4 MB | player 通路（histreamer 1.06MB + ffmpeg 1.36MB，需 recorder 依赖解耦确认）+ js builtin 死库清理 + image_classification.wk 换型 |
| **合计（一二期）** | **~26 MB / rootfs+userfs 53MB 实际内容 ≈ 49%** | 另启动服务 15→6 个（启动时间收益待 T1 打点实测） |

> 注：以上为文件级静态估算；最终以 T6 裁剪实施后**同口径对比构建**实测为准（分区镜像为定长 vfat，收益体现在实际内容占用与烧录/加载时间）。
