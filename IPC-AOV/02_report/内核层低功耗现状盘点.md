## 0. 结论速览（TL;DR）

内核 PM 框架（`kernel/extended/power/los_pm.c`，845 行）**骨架完整**：四档休眠状态机、设备注册链、分档锁否决、时间补偿、idle 自动进入均已就位并可编译进镜像（符号实证）。但**真正的省电执行层是空的**：

1. **tickless 未启用**——`OsPmTickTimerStop()` 恒返回 `FALSE`、`OsPmTickTimerStart()` 空实现（`LOSCFG_KERNEL_PM_SYSTICK_ENABLE` 未定义），tick 永不停走，系统每 1ms 被 tick 中断唤醒一次。这是内核层**最大的功耗缺口**。
2. **light/deep 档均为静默 WFI**——平台钩子 `HiPmLightSuspend`/`HiPmDeepSuspend` 只执行 `WFI`，时钟门控 / DDR 自刷新 / 电源域关断序列**未实现**（依赖海思 CRG/PMU 资料，🔒 NDA）。
3. **无 RTC 唤醒源**——`LOS_PmRegister` 仅注册了 SYSCTRL 节点，未把 RTC alarm 注册为 `LOS_PM_TYPE_DEVICE` 唤醒源；深睡当前靠**任务周期唤醒**，非 RTC 定时唤醒。
4. **SMP 从核仅 WFI park**——`OsIdleTask` 中从核 `while(1) WFI`，无 hotplug / 电源域关断。
5. **无 µA 级计量**——平台仅有 ms 级 tick 差值统计（`HiPmLateResume`），无功耗 profiling 接口。

**本项目已增强（落地+符号实证 ✅）**：K1 分档锁否决/降级、K2/T4b 深睡时间 offset 补偿、K3 设备注册链池化、K4 idle 自动进入休眠、K5 wakeCount 竞态快照。

**仍缺失（⏳/🔒）**：tickless 启用、CRG/PMU 时钟门控、电源域关断（NDA）、RTC alarm 唤醒源、从核深睡、µA 计量。

## 1. PM 状态机与档位模型 `[原生]`

### 1.1 四档休眠枚举

## 2. 锁否决机制（K1 分档锁）`[本项目]`

### 2.1 分档锁计数

`los_pm.c:74-86` `LosPmCB` 结构核心字段：

```c
typedef struct {
    LOS_SysSleepEnum  pmMode;                    // 目标档位（/proc/power/power_mode 设定）
    LOS_SysSleepEnum  sysMode;                   // 本轮实际档位（否决/降级后）
    UINT16            lock[LOS_SYS_SHUTDOWN + 1];// K1：分档锁计数，下标=档位（4 档）
    BOOL              isWake;
    LOS_DL_LIST       deviceList;                // K3：多设备注册链
    UINT32            deviceCount;
    LosPmSysctrl      *sysctrl;
    UINT64            enterSleepTime;
    LOS_DL_LIST       lockList;
} LosPmCB;
```

锁节点 `OsPmLockCB`（`:60-65`）携带 `mode` 字段——**锁声明它否决哪一档及更深档**（`los_pm.h:270-273` 注释：`mode=DEEP` 否决 DEEP/SHUTDOWN 但放行 NORMAL/LIGHT；旧式 `LOS_PmLockRequest` 等价 `mode=NORMAL`，否决所有休眠）。

### 2.2 分档否决/降级逻辑

`OsPmSuspendCheck()`（`los_pm.c:203-227`）：

```c
pm->sysMode = pm->pmMode;
/* K1：找最浅持锁档位；NORMAL 被否决=放弃本轮，更深档被否决=降级到其上一档 */
for (i = 0; i <= (UINT32)pm->pmMode; i++) {
    if (pm->lock[i] > 0) {
        if (i == (UINT32)LOS_SYS_NORMAL_SLEEP) {
            pm->sysMode = LOS_SYS_NORMAL_SLEEP;
            return LOS_NOK;            // NORMAL 被锁 → 本轮不休眠
        }
        pm->sysMode = (LOS_SysSleepEnum)(i - 1);  // 深档被锁 → 降到上一档
        break;
    }
}
```

全档锁总数 `OsPmLockTotalGet()`（`:96-105`）遍历 `lock[0..SHUTDOWN]` 求和；对外经 `LOS_PmLockCountGet()`（`:526-535`，持 `g_pmSpin`）暴露。

**设计意义**：相比上游"一把锁否决全部休眠"，分档锁允许"持有 LIGHT 锁时仍可进 NORMAL WFI"，避免过度阻塞浅睡，是 AOV 常录场景（频繁浅睡）的关键。

## 3. 设备注册链（K3 池化）`[本项目]`

### 3.1 池化节点

### 3.2 注册序 suspend / 逆序 resume

- `OsPmDeviceRegister()`（`:289-330`）：池内找空槽（`device==NULL`），**去重**（同一指针仅注册一次，`:301`），池满报错（`:320`）。
- `OsPmSuspendPrepare()`（`:169-201`）：按注册链**正序**逐个 `device->suspend(mode)`，失败以 `devSuspended` 计数（`:186`）。
- `OsPmResumePrepare()`（`:148-167`）：按**逆序** resume（"越底层越晚睡越早醒"，`:155`），且**仅恢复已挂起的 `devSuspended` 个**（失败回滚不触碰未挂起设备）。
- `LOS_PmRegister()`（`:369-390`）类型分发：DEVICE→注册链；TICK_TIMER→`PRINT_ERR` 返回 EINVAL（reserved 未实现）；SYSCTRL→`OsPmSysctrlRegister`。

**设计意义**：上游 PM 无统一外设挂起链；K3 提供池化、有序、可回滚的多设备 suspend/resume 框架，为第三步真实外设（VICAP/ISP/DDR）电源序列预留挂载点。当前**注册链仅有 sysctrl，无外设 device 节点**（⏳ 待硬件联调填充）。

## 4. 挂起主流程（OsPmSuspendSleep）`[原生骨架 + 本项目 K1/K5]`

`los_pm.c:229-287`，关键路径：

```c
ret = OsPmSuspendCheck(pm, &sysSuspendEarly, &mode);   // K1 分档否决
if (ret != LOS_OK) return ret;                          // NORMAL 被锁→idle 退裸 WFI（常态，不打错误日志）

ret = OsPmSuspendPrepare(...);                          // K3 正序 suspend 外设 + early 钩子
LOS_SpinLockSave(&g_pmSpin, &intSave);
LOS_TaskLock();
if (pm->isWake) goto EXIT;                              // 已置唤醒→放弃
/* K1：临界区二次检查——Check 后新增的当前档及更浅档锁 → 放弃 */
for (i = 0; i <= (UINT32)pm->sysMode; i++)
    if (pm->lock[i] > 0) goto EXIT;
/* K5：wakeCount=调用方锁计数快照（0=不校验）；临界区内计数已变则放弃 */
if ((wakeCount != 0) && (wakeCount != (UINT32)OsPmLockTotalGet(pm))) goto EXIT;

tickTimerStop = OsPmTickTimerStop(pm);                  // 恒 FALSE（tickless 未启用，见 §7）
if (!tickTimerStop) { OsSchedResponseTimeReset(0); OsSchedExpireTimeUpdate(); }
OsPmCpuSuspend(pm);                                     // 分发 normal/light/deep/shutdown suspend
OsPmCpuResume(pm);                                      // 分发对应 resume
OsPmTickTimerStart(pm);                                 // 空实现
EXIT:
pm->sysMode = LOS_SYS_NORMAL_SLEEP;
OsPmResumePrepare(...);                                 // K3 逆序 resume + late 钩子
LOS_SpinUnlockRestore(&g_pmSpin, intSave);
LOS_TaskUnlock();
```

- `OsPmCpuSuspend()`（`:132-146`）按 `sysMode` 调 `sysctrl->normalSuspend/lightSuspend/deepSuspend/shutdownSuspend`。
- **K5 竞态语义**（`:264-267`）：实现 Linux `wakeup_count` 式防丢唤醒——调用方读锁计数快照后传入，临界区内若计数变化说明有并发持锁/唤醒，放弃本轮休眠。`LOS_PmSuspend(wakeCount)`（`:787-791`）透传该参数（idle 传 0=不校验）。

## 5. idle 自动进入休眠（K4）`[本项目，平台侧]`

### 5.1 上游原生 idle `[原生]`

`kernel/base/core/los_task.c:126`（WEAK）：

```c
LITE_OS_SEC_TEXT WEAK VOID OsIdleTask(VOID) {
    while (1) { WFI; }     // 仅 WFI，不接 PM 框架
}
```

> 上游 idle **不调用 `LOS_PmSuspend`**，即默认不进 PM 状态机——这是 L1 低功耗的核心断点。

### 5.2 平台 strong 覆写 `[本项目 K4]`

`device/soc/hisilicon/common/platform/pm/pm_hi35xx.c:148-168`：

```c
LITE_OS_SEC_TEXT VOID OsIdleTask(VOID) {
#ifdef LOSCFG_KERNEL_SMP
    if (ArchCurrCpuid() != 0) { while (1) { WFI; } }   // SMP 从核 park（深睡 park 为第三步课题）
#endif
    HiPmSysctrlRegister();                              // 惰性注册 sysctrl（idle 在 OsPmInit 后运行，时序安全）
    while (1) {
        /* K1 分档锁：Suspend 内部完成否决/降级与竞态二次检查；NORMAL 被否决时退裸 WFI */
        if (LOS_PmSuspend(0) != LOS_OK) { WFI; }
    }
}
```

- **链接机制**：vendor 平台库在 `hdf_lite.mk` 的 `--whole-archive` 区间内链接 → strong `OsIdleTask` 强制覆盖内核 WEAK 版。符号实证：`OHOS_Image.sym.sorted` 中 OsIdleTask 尺寸 **taurus 0x80(128B)**（含从核 park 分支）/ **aries 0x6C(108B)**（UP 无 cpuid 判断），vs 基线 8B。
- **K1 简化**：idle 循环去掉 `LockCountGet` 前置判断，否决/降级逻辑全部收敛进 `LOS_PmSuspend` 内部（临界区原子完成），消除 check-then-act 竞态。

### 6.2 深睡 RTC 差值补偿

`pm_hi35xx.c:94-125`：

```c
STATIC UINT32 HiPmDeepSuspend(VOID) {
    g_pmDeepStartCycle = HalClockGetCycles();
    if (Hi35xxRtcReadEpoch != NULL) Hi35xxRtcReadEpoch(&g_pmDeepStartEpoch);  // 弱引用，无 RTC 驱动自动退化
    /* 第三步在此插入电源域关断序列（依赖海思低功耗 SDK，NDA） */
    WFI;
    return LOS_OK;
}
STATIC VOID HiPmDeepResume(VOID) {
    if (Hi35xxRtcReadEpoch(&epochNow) != 0) return;
    elapsedCycle    = HalClockGetCycles() - g_pmDeepStartCycle;
    rtcElapsedCycle = (epochNow - g_pmDeepStartEpoch) * PM_CYCLES_PER_SEC;
    if (rtcElapsedCycle > elapsedCycle)
        LOS_PmTimeOffsetAdd(rtcElapsedCycle - elapsedCycle);   // 补偿 CNTPCT 掉电丢失的 cycles
}
```

> **当前态**：deepSuspend 仅 WFI，CNTPCT 不停走 → `rtcElapsedCycle ≈ elapsedCycle` → offset 增量≈0（机制自校验，无副作用）。**第三步真实电源域关断后**（CNTPCT 掉电），该路径才产生非零补偿。LIGHT 档 CNTPCT 不停走，自动退化。

## 7. tick / tickless（关键缺口）`[缺失 ⏳]`

### 7.1 tick 永不停走

`los_pm.c:109-119`：

```c
STATIC VOID OsPmTickTimerStart(LosPmCB *pm) { (VOID)pm; return; }        // 空实现
STATIC BOOL OsPmTickTimerStop(LosPmCB *pm)  { (VOID)pm; return FALSE; }  // 恒 FALSE=未停 tick
```

`OsPmSuspendSleep:268` 调 `OsPmTickTimerStop` 得 FALSE → 走 `OsSchedResponseTimeReset/ExpireTimeUpdate` 分支（按"tick 仍在走"处理）。

### 7.2 根因：配置未启用

- `LOSCFG_KERNEL_PM_SYSTICK_ENABLE`：**全树未定义**（config.h 无此项）。
- `LOSCFG_KERNEL_PM_SWTMR_ENABLE`：**全树未定义**。
- `LOSCFG_BASE_CORE_TICK_PER_SECOND = 1000`（`los_config.h:96`，1ms/tick）。

**后果**：即使进入 NORMAL/LIGHT/DEEP，系统每 1ms 被 tick 中断唤醒一次重新调度。对 AOV"长睡短醒"模型，这是**功耗地板**——无法进入真正的长周期休眠。

**补齐路径（⏳ 第二步）**：启用 `LOSCFG_KERNEL_PM_SYSTICK_ENABLE`，实现 `OsPmTickTimerStop/Start`（停/恢复硬件 tick），配合 K3 阈值（idle 预估睡眠时长 < 阈值则不值得停 tick）；唤醒源需含 RTC alarm（§9）。**阻塞**：tick 停走后软定时器/调度时钟须由 offset 补偿（§6 已具备框架），但停 tick 的硬件操作与唤醒延迟需板卡实测标定。

## 9. RTC 与 SNTP 校时 `[本项目 T4b]`

### 9.1 RTC epoch 读取

`device/soc/hisilicon/common/platform/rtc/rtc_hi35xx.c:916-933`：

```c
int Hi35xxRtcReadEpoch(long long *epochSec) {
    if (g_rtcTimeSyncHost == NULL || epochSec == NULL) return HDF_FAILURE;
    if (HiRtcReadTime(g_rtcTimeSyncHost, &rt) != HDF_SUCCESS) return HDF_FAILURE;
    if (rt.year < RTC_TIME_YEAR_START || rt.year > RTC_TIME_YEAR_END) return HDF_FAILURE;
    days = HiRtcCivilToDays(rt.year, rt.month, rt.day);   // Howard Hinnant 算法（:814），不依赖内核 mktime
    *epochSec = days*SEC_PER_DAY + rt.hour*SEC_PER_HOUR + rt.minute*SEC_PER_MIN + rt.second;
    return HDF_SUCCESS;
}
```

`Hi35xxRtcWriteSysTime()`（`:879`）：`gettimeofday` → 写 RTC（掉电重启不丢时间）。

### 9.3 唤醒源缺口 `[缺失 ⏳]`

RTC 当前仅用于**时间补偿**（§6.2），**未注册为 PM 唤醒源**（`LOS_PM_TYPE_DEVICE` 注册链中无 RTC alarm 节点）。深睡唤醒依赖任务周期（`LOS_TaskDelay`）而非 RTC alarm 定时——这是"长睡"无法落地的直接原因之一，与 §7 tickless 缺口耦合。补齐需：RTC alarm 中断 → `LOS_PmDeviceRegister` 唤醒回调 → 停 tick 后由 RTC 唤醒重校时间轴。

## 10. syscall / proc 接口

### 10.1 proc 控制面 `[原生 + 本项目对接]`

- `/proc/power/power_mode`：切换 normal/light/deep（`pm_hi35xx.c:25,145`）。
- `/proc/power/power_lock` + `/proc/power/power_unlock`：PM 锁计数（`powermgr_lite/services/src/power/small/running_lock_handler.c:73,78`），**RunningLock 已对接内核 PM 锁**。

### 10.2 用户态挂起桩 `[本项目]`

`base/powermgr/powermgr_lite/services/src/power/small/auto_suspend_loop.c:18-37`：

```c
/* 真实挂起已由内核 PM idle 钩子接管（pm_hi35xx.c）：idle 无锁时自动 LOS_PmSuspend。
 * 挂起准入仍经 WakeupHolder RunningLock 生效。本循环仅保留为后续用户态挂起策略槽位，
 * 不再以 sleep 模拟挂起（原实现误导且产生 10s 周期无效唤醒）。 */
static BOOL AutoSuspendLoopFunc(AutoSuspendWait waitFunc) {
    waitFunc();
    sleep(SUSPEND_POLICY_IDLE_TIME);   // 3600s，占位
    return TRUE;
}
```

> 上游 small 系统用 `sleep` 模拟挂起（误导 + 周期无效唤醒）；本项目改为**内核 idle 钩子接管真实挂起**，用户态循环退化为策略槽位。

### 10.3 syscall 权限 `[本项目 T2]`

`LOS_PmSuspend` 经 syscall 暴露需 `CAP_POWER` 权限；本项目修复了 proc 权限与 `ReadLock` 语义（T2），使 RunningLock→PM 锁链路贯通（详见《T1T2T3 补丁开发报告》）。
