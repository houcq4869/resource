# 04 · 工程化与毕业项目

> 配对练习：`project/todo-cli.js`。前 15 题给你语言，这一章给你"项目该怎么组织"。

## 1. 模块：没有 #include 的世界

JS 模块是**运行时真正加载的独立作用域**——没有头文件、没有 include guard、没有前向声明，导出什么、导入什么清清楚楚。

两套体系并存，先认脸：

### CommonJS（Node 传统格式，你的练习用的就是它）

```js
// store.js
function add() {}
module.exports = { add };          // 导出

// main.js
const { add } = require('./store');  // 导入：解构取值
const fs = require('node:fs/promises'); // Node 内置模块，node: 前缀是好习惯
```

- `require` 是同步的、动态的：需要时才加载，返回 `module.exports` 对象
- 本目录没有 `package.json`，`.js` 按 CJS 处理（你的练习能直接跑就是这个原因）

### ES Modules（浏览器标准 / 新项目推荐）

```js
// store.mjs（或 package.json 里加 "type": "module"）
export function add() {}

// main.mjs
import { add } from './store.mjs';
import { readFile } from 'node:fs/promises';
```

- `import` 静态提升；支持顶级 `await`；没有 `__dirname`（用 `import.meta.dirname`）
- 新项目建议 ESM。本教程练习为了"零配置直接跑"用了 CJS——两套都认识即可，语法差异 5 分钟就能迁移

对照 C：`#include` 是文本复制粘贴，重复包含要靠 include guard；`require/import` 是真正的加载与隔离，**循环依赖也有确定规则**（但别写循环依赖）。

## 2. npm 与 package.json

npm ≈ CMake + vcpkg/conan 的合体。

```bash
npm init -y              # 生成 package.json（项目清单）
npm install lodash       # 装包 → node_modules/ + 记入 package.json 依赖
npm install              # 克隆项目后一键装齐所有依赖
npx cowsay hello         # 临时运行一个包的 CLI，不污染项目
```

`package.json` 核心字段：

```json
{
  "name": "todo-cli",
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "start": "node app.js",
    "test": "node --test"
  },
  "dependencies": { "lodash": "^4.17.21" }
}
```

- `scripts`：`npm start` / `npm run test` 是跨平台的 make 惯例（`^` 表示"兼容的小版本更新"）
- `node_modules` 加入 `.gitignore`（等价于不提交 vcpkg 的安装目录）；`package-lock.json` **要**提交（锁版本）

## 3. 毕业项目 todo-cli：路线图

不给完整答案，给行军路线。卡住了再往回翻对应章节。

### Step 1：最小闭环（load / save / add / list）

这一步的重点是**文件持久化 + 命令分发**，用到：

```js
const fs = require('node:fs/promises');
const path = require('node:path');

const FILE = path.join(__dirname, 'todos.json');

async function load() {
  try {
    const raw = await fs.readFile(FILE, 'utf8');   // 返回 Promise<string>
    return JSON.parse(raw);
  } catch (e) {
    return [];          // 文件不存在 / 内容为空，都当空数组
  }
}

async function save(todos) {
  await fs.writeFile(FILE, JSON.stringify(todos, null, 2));  // null, 2 = 美化缩进
}
```

坑位提示：

- `process.argv` ≈ `argc/argv`，但 `argv[0]` 是 node、`argv[1]` 是脚本路径——所以取命令用 `const [,, cmd, ...args] = process.argv`
- `JSON.parse('')` 会抛异常——空文件要 catch（上面的 try/catch 已覆盖）
- 每个命令都是"load → 修改 → save → 打印"结构，重复结构就是你拆 `store.js` 模块的信号

### Step 2：done / remove

- 命令行参数永远是**字符串**：`done 1` 里拿到的是 `'1'`，用 `Number(id)` 转
- 数组方法复习（第一章）：`find`（定位）、`filter`（删除=`filter(t => t.id !== id)`）、`map`（打印）
- 找不到 id 打印提示，别静默失败

### Step 3：加分项（自选）

1. `list` 时未完成排前面：`sort((a, b) => Number(a.done) - Number(b.done))`
2. 把 load/save 拆成 `store.js`，主文件只管命令分发——体会 CJS 模块
3. 用 ESM 格式重写一遍（`"type": "module"` + `import/export`）——两套模块体系都上手
4. 数据文件损坏时的容错

### 验收标准

```bash
node todo-cli.js add "买牛奶"
node todo-cli.js add "写周报"
node todo-cli.js list          # 看到 2 条
node todo-cli.js done 1
node todo-cli.js list          # 第一条打了勾
node todo-cli.js remove 2
node todo-cli.js list          # 只剩 1 条
cat todos.json                 # 人类可读的 JSON
```

## 4. TypeScript 预览（10 分钟）

写到这里，你可能开始想念 C++ 的类型了——**TypeScript 就是把类型系统请回来**：

```ts
interface Todo {
  id: number;
  text: string;
  done: boolean;
}

function add(todos: Todo[], text: string): Todo {
  return { id: nextId(todos), text, done: false };
}

const x: number = add([], "hi");   // 编译报错：Todo 不能赋给 number
```

- TS = JS + **编译期**类型检查，编译产物是普通 JS。你 95% 的 JS 知识原样复用
- 类型是"渐进的"：可以先 JS 后补类型，也可以全程严格
- 体验：`npm install -g typescript` 后 `tsc --strict app.ts`，或者 `npx tsx app.ts` 直接运行
- **建议时机**：完成 todo-cli 后，把它用 TS 重写一遍——你会感觉"回家的感觉"
