# 01 · 类型与语法：动态语言的纪律

> 配对练习：`01-syntax/`（练习 1 你已 8/8 通过——本章相当于那份坑题的"答案解析 + 延伸"）

## 1. 类型系统总览

JS 只有 **7 种原始类型 + 1 种对象类型**，`typeof` 的返回值并不完全对应：

| `typeof x` 的结果          | 实际类型               | C/C++ 对照                            |
| ----------------------- | ------------------ | ----------------------------------- |
| `"number"`              | 任意数字（含小数）          | `double`（**没有 int/float/long 之分！**） |
| `"string"`              | 字符串                | 不可变 + 自带一堆方法，无直接对应                  |
| `"boolean"`             | `true` / `false`   | `bool`                              |
| `"undefined"`           | "从未赋值"             | 无对应，类似语言级集成的"空槽位"                   |
| `"object"`              | 对象 / 数组 / **null** | `struct` 和 hash map 二合一             |
| `"function"`            | 函数                 | 函数指针（但携带闭包环境）                       |
| `"symbol"` / `"bigint"` | 暂时忽略               | —                                   |

两个反直觉点（练习 1 已踩过）：

- `typeof null === "object"`：1995 年的历史 bug，永久保留
- `typeof function(){}` 是 `"function"`，函数是"一等公民"（第二章的主角）

### 数字：只有 double 一种

```js
5 / 2        // 2.5 —— 没有整除截断！整除要写 Math.floor(5 / 2)
0.1 + 0.2    // 0.30000000000000004 —— 和 C 的 double 一样
```

需要超过 `2^53 - 1` 的精确整数（如哈希值、ID），用 `BigInt`：字面量加 `n` 后缀。

```js
9007199254740993n + 1n   // 精确，9007199254740994n（普通 number 会丢精度）
```

### `===` 是唯一的比较方式

`==` 的隐式转换规则表（`"1" == 1`、`null == undefined`、`[] == ![]`……）不值得背——写得出这种规则的人自己也会错。

**纪律：永远 `===`；需要类型转换时显式写 `Number(x)` / `String(x)`。** 读老代码遇到 `==` 再去查表（MDN：相等性比较）。

### `undefined` vs `null`

```js
let x;                       // x === undefined：从未赋值
const y = null;               // 必须显式赋值才出现 null
function f(a) { return a; }  // f() 里 a === undefined（少传的参数）
f(1, 2);                      // 多传的参数被静默忽略
```

类比：`null` ≈ 你手动设的 `nullptr`（"明确置空"）；`undefined` ≈ "这个槽位里从来就没放过东西"。

## 2. 变量声明：`let` / `const` / `var`

**纪律：默认 `const`，需要重新赋值才 `let`，`var` 只需认得（老代码）不需要会写。**

`var` 的两宗罪——函数作用域 + 提升：

```js
function demo() {
  console.log(a);   // undefined —— 不报错！var 声明被"提升"到函数顶部，值为 undefined
  if (true) {
    var a = 1;      // var 无视块结构，作用域是整个函数
    let b = 2;
  }
  console.log(a);   // 1 —— 块结束后依然活着
  console.log(b);   // ReferenceError —— let 是块作用域，b 已死
}
```

对照 C：C 的块级作用域天经地义，`let`/`const` 就是这个语义；`var` 是历史包袱。

### TDZ：比 C 更安全的"未初始化"

```js
{
  console.log(x);   // ReferenceError: Cannot access 'x' before initialization
  let x = 1;
}
```

声明之前的区域叫**暂时性死区（TDZ）**。注意它和 `var` 的区别：`var` 提升后给你 `undefined`（静默错误），`let` 直接抛异常（快速失败）——动态语言里这是好事。

### `const` 锁的是"绑定"，不是"值"

```js
const arr = [];
arr.push(1);     // ✓ 合法！const 只禁止 arr = 别的东西
arr = [];        // ✗ TypeError
```

想锁内容：`Object.freeze(arr)`（浅冻结）。

## 3. 字符串：不可变 + 模板字面量

```js
const s = 'hello';
s[0] = 'H';          // 静默无效（严格模式下 TypeError）—— 字符串不可变
s.toUpperCase();      // 返回新字符串 'HELLO'，s 不变
```

**模板字面量**是 C 里没有的东西（相当于自带 `sprintf` 且类型安全）：

```js
const name = 'Ada';
const greeting = `你好, ${name}!
你已经有 ${3 + 4} 天没提交代码了`;   // ${} 里放任意表达式，还支持真·多行
```

常用方法：`slice` / `includes` / `indexOf` / `trim` / `split` / `padStart`。
一个坑：字符串按 UTF-16 编码单元计数，`'𠮷'.length === 2`（生僻字是代理对）。日常英文/中文无感，知道即可。

## 4. 数组：本质是对象

### 没有"越界"这回事

```js
const a = [1, 2, 3];
a[10];    // undefined —— 不 UB、不报错、返回 undefined
a[-1];    // undefined —— 不是"最后一个元素"！要用 a.at(-1) 或 a[a.length - 1]
```

对照 C：没有边界检查的 UB 风险，代价是错误被静默吞掉——**动态语言的税**。

### sort 的默认行为是个大坑

```js
[10, 9, 1].sort();              // [1, 10, 9] —— 默认按【字符串】比较！
[10, 9, 1].sort((a, b) => a - b); // [1, 9, 10] —— 数值排序必须给比较器
```

（相当于 `qsort` 不传比较函数时拿 `strcmp` 比数字——JS 把这个坑做成了默认值。）

### map / filter / reduce：你的 STL 算法直觉直接复用

| JS                                             | C++ 等价物                         |
| ---------------------------------------------- | ------------------------------- |
| `arr.map(f)`                                   | `std::transform`                |
| `arr.filter(p)`                                | `std::copy_if`                  |
| `arr.reduce(f, init)`                          | `std::accumulate`（但通吃一切"折叠"操作）  |
| `arr.find(p)` / `arr.some(p)` / `arr.every(p)` | `find_if` / `any_of` / `all_of` |

```js
const nums = [3, 1, 4, 1, 5];
nums.map(x => x * 2);              // [6, 2, 8, 2, 10] —— 新数组，不改原数组
nums.filter(x => x % 2 === 0);     // [4]
nums.reduce((acc, x) => acc + x, 0); // 14 —— 第二参数是初始值，必给
```

注意：`forEach` **没有 break**——要提前退出用 `for...of`，或 `some`（返回 true 即停）：

```js
for (const x of nums) {
  if (x > 4) break;   // for...of 是正统的带 break 遍历
}
```

## 5. 对象：动态的 struct + hash map

```js
const user = { name: 'Ada', 'favorite lang': 'C++' };
user.age = 36;          // 运行时加属性
delete user.age;        // 运行时删属性
'name' in user;         // 判断属性存在
Object.keys(user);      // ['name', 'favorite lang']
Object.values(user);    // ['Ada', 'C++']
```

C 结构体的字段编译期定死；JS 对象随时增删。JS 对象本质是"字符串键 → 值"的哈希表。

### 解构与展开：高频语法糖

对照 C++ 的 structured bindings（`auto [name, age] = user;`），JS 版本更强大：

```js
const { name, age } = user;            // 基本解构
const { name: n } = user;              // 重命名
const { city = 'Beijing' } = user;     // 默认值（属性缺失时）
const { name, ...rest } = user;        // rest：剩余的全部收走

const merged = { ...defaults, ...userPrefs };  // 展开合并，后者覆盖前者
const copy = [...arr];                          // 数组浅拷贝（新数组，元素引用共享）
```

**浅**拷贝/浅合并：嵌套的对象仍然共享引用，深层拷贝要递归或 `structuredClone`。

## 6. GC：和 C 的彻底决裂

- 没有 `free` / `delete` / RAII / 析构函数
- 主流引擎（V8）用 **标记-清除**：从"根"（全局对象、当前调用栈）出发标记所有可达对象，其余回收
- 你的肌肉记忆要反过来：在 C 里你担心"忘了释放"；在 JS 里你担心"**意外让大对象一直可达**"：

```js
// 经典泄漏模式（现在看不懂没关系，学完第二三章回头看）
const cache = new Map();          // ① 无上限的缓存只增不减
setInterval(fn, 1000);            // ② 忘了 clearInterval，回调持有的大对象永不回收
function outer() {
  const huge = new Array(1e6).fill(0);
  return () => huge[0];           // ③ 闭包无意捕获 huge，一个字节都不放过
}
```

- 清理资源（文件、网络连接）没有析构函数，必须显式 `close()` / 用 `try...finally`（第三、四章实践）

## 8. 自测（答案在下方）

1. `const x = [1]; x.push(2)` 合法吗？为什么？
2. `typeof null` 和 `typeof undefined` 分别是什么？
3. `[10, 9, 100].sort()` 的结果？怎么修正？
4. 为什么 `forEach` 里不能 `break`？替代方案是什么？

<details>
<summary>答案</summary>

1. 合法。`const` 锁定的是"变量名与值的绑定"，数组内容可变。
2. `"object"` 和 `"undefined"`。
3. `[10, 100, 9]`——默认字符串比较，`"100" < "10" < "9"`。修正：`.sort((a, b) => a - b)`。
4. `forEach` 只管逐个调用回调，没有检查回调返回值的机制。替代：`for...of`（可 break），或 `some` / `every`。
</details>
